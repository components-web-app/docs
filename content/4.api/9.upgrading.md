---
title: Upgrading the Bundle
description: What changes between api-components-bundle releases, and the steps to take for each one, newest first.
---

Each section below covers one release of `components-web-app/api-components-bundle`, newest first. Work through every section between your current version and the one you're moving to, oldest first. The other pages in this section describe the current release only.

The full list of changes, including fixes that need no action, is in the bundle's [`CHANGELOG.md`](https://github.com/components-web-app/api-components-bundle/blob/main/CHANGELOG.md) and on its [GitHub releases](https://github.com/components-web-app/api-components-bundle/releases). If you use the components-web-app template, also see [Upgrading the Template](/deployment/upgrading-the-template), which pins each bundle release with the matching `@cwa/nuxt`.

::callout{icon="i-heroicons-information-circle"}
**Generating a migration.** Several releases add a table or a column. Run `php bin/console doctrine:migrations:diff`, check the generated file, delete its `down()` (migrations are [upward-only](/api/bundle-setup#database-setup)), then run `php bin/console doctrine:migrations:migrate`. The template's entrypoint runs pending migrations when the API pod starts.
::

## 2.0.0-alpha.10

Released 2026-10-10.

**Do this:**

- [ ] Nothing is required. To move to `symfony/mercure` 0.9 and `symfony/mercure-bundle` 0.6, set `cookie_name: '__Secure-mercure_access_token'` on the hub in `mercure.yaml` first. Otherwise 0.6 sets `mercure_access_token` while `kernel.debug` is on, the hub doesn't read it, and admins get no private updates in development. Also replace any use of the removed `Publisher`, `PublisherInterface`, `TraceablePublisher` or `StaticJwtProvider` services with `HubInterface`, `TraceableHub` or `StaticTokenProvider`. See [Bundle Setup → `mercure.yaml`](/api/bundle-setup#mercureyaml).

**What changed:**

- **Mercure 0.9 and mercure-bundle 0.6 are allowed** ([#385](https://github.com/components-web-app/api-components-bundle/pull/385)). The bundle accepts `symfony/mercure` ^0.8 || ^0.9 and `symfony/mercure-bundle` ^0.5 || ^0.6. mercure-bundle 0.6 defaults to the 1.0 protocol and leaves `url` and `public_url` null by default. Keep setting `protocol_version: '1.0'`, `url` and `public_url` explicitly.

**Do this:**

- [ ] Update `@cwa/nuxt` to `2.0.0-alpha.8` in the same deploy. Its **Public without a route** toggle reads and writes the new column.

A page or page data with no route and `isReachableWithoutRoute` set is readable as though a live route reached it, so an application can serve it from a route of its own. ## 2.0.0-alpha.8

Released 2026-10-04.

**Do this:**

- [ ] **Move the Mercure hub to the 1.0 protocol in the same deploy** ([#379](https://github.com/components-web-app/api-components-bundle/pull/379)). The bundle now speaks only Mercure 1.0 and requires `symfony/mercure` ^0.8 and `symfony/mercure-bundle` ^0.5 (from alpha.10, ^0.9 and ^0.6 work too). In `mercure.yaml`, set `protocol_version: '1.0'` and the `jwt.claims` `iss`, `sub` and `client_id`. In the hub's Caddyfile, move the keys into an `issuer <iss> { publisher { jwt … } subscriber { jwt … } }` block matching `iss`, pin `resource_identifier` to the public hub URL, and drop `protocol_version_compatibility`. The hub URL must be `https://`, because the subscriber cookie is now `__Secure-mercure_access_token`; on a plain-HTTP hub, set a prefix-less `cookie_name` on both sides. See [Bundle Setup → Mercure Hub](/api/bundle-setup#mercure-hub).
- [ ] Update `@cwa/nuxt` to `2.0.0-alpha.4` or later at the same time. Older modules subscribe with `topic=`, which a Mercure 1.0 hub rejects. Anything of your own that read the `mercureAuthorization` cookie must change.
- [ ] Generate and run a migration for the orphaned file report table, `_acb_orphaned_file_report` ([#373](https://github.com/components-web-app/api-components-bundle/pull/373)).
- [ ] **Check `use_symfony_listeners`** ([#369](https://github.com/components-web-app/api-components-bundle/pull/369)). The bundle no longer forces `api_platform.use_symfony_listeners: true`, so it follows API Platform's default (off). The bundle works either way. If your own code hooks API resources through `EventPriorities` or `kernel.view`/`kernel.request` listeners, move it to a state provider or processor decorator, or set the flag to `true` yourself. Up to alpha.7, setting it to `false` broke requests such as `GET /_api/me`.
- [ ] If you referenced the bundle's listener classes, update them. Removed: `DenyAccessListener`, `ComponentUsageEventListener`, `RouteEventListener`, `DeletedResourceEventListener` and `UploadableEventListener`. Renamed: `UserEventListener` → `Helper\User\UserWriteNotifier` (`postWrite()` → `notify()`), `CollectionApiEventListener` → `Helper\Collection\CollectionPopulator` (`transform()` → `populate()`), and the draft merge moved from `PublishableEventListener` to `Helper\Publishable\PublishableDraftMerger`. Upload and download operations run from `UploadStateProvider`/`DownloadStateProvider` instead of custom controllers. The changelog has the new service ids.
- [ ] Optional: point your liveness probe at the new `GET /_/health/live` and keep `GET /_/health` for readiness. See [Kubernetes → The API's health endpoints](/deployment/kubernetes#the-apis-health-endpoints).
- [ ] Optional: after the upgrade, run [`scan-orphaned-files`](/api/console-commands#scan-orphaned-files) to find files that earlier releases left in storage (see below).

**What changed:**

- **Stored files are deleted however their resource is removed** ([#372](https://github.com/components-web-app/api-components-bundle/pull/372)). Up to alpha.7, only a direct `DELETE` removed the file. A resource removed by a cascade, an orphan delete or your own code left its file in storage, and a direct `DELETE` removed the file before the row, so a failed delete lost it ([#370](https://github.com/components-web-app/api-components-bundle/issues/370)). See [Uploadable → Removing the resource](/api/components/annotations/uploadable#removing-the-resource).
- **The orphaned file report** ([#373](https://github.com/components-web-app/api-components-bundle/pull/373)): the `scan-orphaned-files` command and the `/_/orphaned_files` endpoints. See [`scan-orphaned-files`](/api/console-commands#scan-orphaned-files).
- **`GET /_/health/live`** ([#375](https://github.com/components-web-app/api-components-bundle/pull/375)), a liveness check that touches no database, cache or remote service.

## 2.0.0-alpha.7

Released 2026-09-26.

**Do this:**

- [ ] Nothing is required. If you worked around the alpha.6 recipient problems below, you can undo the workaround.

**What changed:**

- **`orphaned_resources.notify.recipients` accepts `Name <address>`** ([#363](https://github.com/components-web-app/api-components-bundle/pull/363)). On alpha.6 ([#361](https://github.com/components-web-app/api-components-bundle/issues/361)), that form failed the container build when written in the config file. Supplied by an environment variable, it was logged as invalid and nothing was sent, so every run tried again.

## 2.0.0-alpha.6

Released 2026-09-26.

**Do this:**

- [ ] Generate and run a migration for the orphaned resource report table, `_acb_orphaned_resource_report` ([#354](https://github.com/components-web-app/api-components-bundle/pull/354)). Up to alpha.5, the report was kept in Symfony's `cache.app` pool. It isn't carried over, so `GET /_/orphaned_resources` returns `404` until the next scan. `generatedAt` now has microseconds, such as `2026-09-26T01:40:07.123456+00:00`; update `@cwa/nuxt` to `2.0.0-alpha.3` or later so the admin reads it.
- [ ] **Stop relying on `clean-orphaned` to delete** ([#353](https://github.com/components-web-app/api-components-bundle/pull/353)). Up to alpha.5 it deleted orphaned groups and components. It is now an alias of `scan-orphaned` and deletes nothing, so a cron job or deploy step that ran it keeps working but only refreshes the report. Delete orphans with [`POST /_/orphaned_resources/delete`](/api/console-commands#deleting-orphans), or `DELETE` each IRI.
- [ ] Optional: set `orphaned_resources.notify.recipients` to have `scan-orphaned` email when the orphans change. On this release, use bare addresses and never `null` (fixed in alpha.7, above). See [Emailing when orphans change](/api/console-commands#emailing-when-orphans-change).
- [ ] **Check components held by a parent-typed page data property** ([#349](https://github.com/components-web-app/api-components-bundle/pull/349)). Up to alpha.5, a page data property typed as a parent class (`ManyToOne(targetEntity: AbstractComponent::class)`, or a class the component extends) wasn't seen as a location. A component held only that way was readable by anyone. It now follows the page data: public only while the page data is reachable from a live route, and otherwise limited to users who pass `routable_security`. Editing it also purges the page data from the cache and publishes it to Mercure, which it didn't before. The old `clean-orphaned` and the `/usage` count didn't count it either, so that command could delete a component the report left alone.
- [ ] If you used `generate-fixtures` with a file name other than `GeneratedScaffold.php`, regenerate or rename the class. Up to alpha.5 the class was always `App\DataFixtures\GeneratedScaffold`, whatever the file name, and there was no `--namespace`.

**What changed:**

- **Orphans:** `POST /_/orphaned_resources/delete` ([#353](https://github.com/components-web-app/api-components-bundle/pull/353)). The scan lists what is orphaned only through an orphaned parent, to any depth, and unreachable cycles; up to alpha.5 the report listed only the top of such a chain ([#358](https://github.com/components-web-app/api-components-bundle/pull/358)). An API `DELETE` of a group, page, layout or page data now cascades like the orphan delete; before, a component removed with them left its own groups without an owner and its draft behind as a standalone component. `scan-orphaned` compares with the orphans at the last alert, not the stored report; before [#356](https://github.com/components-web-app/api-components-bundle/pull/356), an admin's scan or delete absorbed the change and nothing was emailed. See [`scan-orphaned`](/api/console-commands#scan-orphaned).
- **Fixtures** ([#347](https://github.com/components-web-app/api-components-bundle/pull/347), [#352](https://github.com/components-web-app/api-components-bundle/pull/352)): see [Data Fixtures](/api/data-fixtures).
  - `PageBuilder::withoutRoute()` is new (`PageDataBuilder` had it already). Up to alpha.5, `generate-fixtures` gave a non-template page with no route a generated one on reload.
  - `generate-fixtures` names the class after the `--output` file, and `--namespace` sets its namespace.
  - Two scaffold classes in one load work. Up to alpha.5 the builder carried the first scaffold's entities into the second, and saving them failed because they were detached.
  - `getRoute()` also finds routes already saved in the database. Up to alpha.5, only routes the scaffold declared were found.
  - A `redirect()` whose derived name is taken gets a suffix. Up to alpha.5 the builder checked a redirect's path but not its name, so a taken name failed on the unique constraint.
  - A `redirect()` whose explicit `name:` belongs to a route created in the same load throws even when its path already exists. Before #352, it threw only when the path was free; otherwise the name was pointed at the route already at that path.

## 2.0.0-alpha.5

Released 2026-09-25.

**Do this:**

- [ ] **A custom route generator must implement `generatePath()`** ([#335](https://github.com/components-web-app/api-components-bundle/pull/335)). If your application replaces or decorates `RouteGeneratorInterface`, add `generatePath(RoutableInterface $object): string`, or PHP refuses to load the class. See [Dynamic Pages → Route Generation](/api/dynamic-pages#route-generation).
- [ ] **Handle `429` from the email request endpoints** ([#332](https://github.com/components-web-app/api-components-bundle/pull/332)). A throttled password reset, email verification or new email confirmation request returns `429` with `Retry-After`. Up to alpha.4 it returned `200` and sent nothing. Each flow now has its own throttle: `user.email_verification.repeat_ttl_seconds` and `user.new_email_confirmation.repeat_ttl_seconds` are new (default 300), and `password_reset.repeat_ttl_seconds` governs only password resets, where it used to throttle all three. A cross-origin front end needs `Retry-After` in its CORS `expose_headers`. See [Throttled and Failed Email Requests](/api/users-and-security#throttled-and-failed-email-requests).
- [ ] Optional: load fixtures with `doctrine:fixtures:load --append`. It now creates only what is missing and keeps existing content ([#335](https://github.com/components-web-app/api-components-bundle/pull/335)). Up to alpha.4, the scaffold stopped at the first page route that already existed and wrote nothing. See [Appending to an Existing Site](/api/data-fixtures#appending-to-an-existing-site).

**What changed:**

- **Registration and a new email address request return `201` when the link is refused** ([#327](https://github.com/components-web-app/api-components-bundle/pull/327)). In alpha.4 they returned `400` even though the user had been saved. The refusal is logged at error level. See [When a link is refused](/api/users-and-security#when-a-link-is-refused).
- **The fixture builder** gained `allow:` on page groups, `liveAt()`, `redirect()`, `afterRoutes()` and `PageDataBuilder::withoutRoute()` ([#322](https://github.com/components-web-app/api-components-bundle/pull/322), [#335](https://github.com/components-web-app/api-components-bundle/pull/335)).
- **The orphaned resource report** (`POST /_/orphaned_resources/scan`, `GET /_/orphaned_resources`) is new ([#329](https://github.com/components-web-app/api-components-bundle/pull/329)).

## 2.0.0-alpha.2

Released 2026-09-24. The first 2.x release since `2.0.0-alpha.1` in 2020, so the jump from 1.x or alpha.1 is large: it requires PHP 8.5, Symfony ^7.4 || ^8.1, API Platform ^4.4 || ^5.0 and Doctrine ORM 3. The changelog lists every breaking change. These are the ones that need action or change what clients see.

**Do this:**

- [ ] Generate and run a migration. Among other things, `Route.liveAt` adds one nullable `live_at` column to the route table (`_acb_route` with the default `table_prefix`) with a `CURRENT_TIMESTAMP` default, so every existing route is marked live ([#229](https://github.com/components-web-app/api-components-bundle/pull/229)). See [Scheduling and Taking Routes Offline](/api/dynamic-pages#scheduling-and-taking-routes-offline).
- [ ] **Replace `OrSearchFilter` and per-field search parameters with `search`** ([#297](https://github.com/components-web-app/api-components-bundle/pull/297), [#303](https://github.com/components-web-app/api-components-bundle/pull/303)). `OrSearchFilter` is removed: an entity that declares `#[ApiFilter(OrSearchFilter::class, ...)]` no longer compiles. The bundle's own collections take a single `search` parameter. The per-field parameters (`?reference=`, `?uiComponent=`, `?title=`, `?path=`) are ignored, several values for one field (`?path[]=a&path[]=b`) no longer work, and the Page search no longer matches `layout.reference`. Sort parameters are unchanged. See [Searching and Sorting](/api/dynamic-pages#searching-and-sorting).
- [ ] **Expect filtered collections to return fewer rows** ([#238](https://github.com/components-web-app/api-components-bundle/pull/238)). `OrSearchFilter`, the search filter on `Route.path`, Page and Layout, built its clauses with `orWhere()`, which ORs against the whole query, so any filter parameter discarded the publication checks. Anonymous `GET /_/routes?path=…` returned scheduled and draft routes, and a filtered collection of a publishable resource returned drafts. Anything that relied on that stops seeing them. See [Publishable → Filtered Collections](/api/components/annotations/publishable#filtered-collections).
- [ ] **Check unrouted pages** ([#233](https://github.com/components-web-app/api-components-bundle/pull/233)). With `routable_security` set, components on a page that nothing routes to used to be publicly readable even though the page was not. They are now private too. Give such a page a Route, place it under a routed one, or, from alpha.9, mark it public without a route. See [Public Access Follows Routes](/api/users-and-security#public-access-follows-routes).
- [ ] **`POST /_/site_config_parameters` needs `publishable.permission`** (usually `ROLE_ADMIN`), like updating or deleting a parameter. Before, the `POST` operation had no security of its own, so an application that creates site config parameters as a non-admin user gets a `403`.
- [ ] **Form `POST` is a full submit** ([#280](https://github.com/components-web-app/api-components-bundle/pull/280)). `POST` used to be partial: on a form without a `data_class`, a required field the request left out was never validated. A client that posts only some fields now gets a `422`. A valid `PATCH` no longer dispatches `FormSuccessEvent` ([#264](https://github.com/components-web-app/api-components-bundle/pull/264)). See [Form Component](/api/components/built-ins/form-component).
- [ ] **`urlGenerator: 'public'` honours the filesystem's `public_url`** ([#269](https://github.com/components-web-app/api-components-bundle/pull/269)). Before, only the adapter was checked, so a field with only `public_url` configured got the `/download/{property}` API URL. If you relied on the API route for such a field, set `urlGenerator: 'api'`.
- [ ] Give each `#[UploadableField]` on a multi-file entity its own `property:`. Two fields sharing one storage property now throw `UnsupportedAnnotationException` at boot instead of sharing a column. Replace an app-side `RequiresUploadedFileTrait` with `requiredOnPublish: true` on the field.
- [ ] **Check clients that expected `500` for client errors** ([#295](https://github.com/components-web-app/api-components-bundle/pull/295)). The bundle's exception mappings used to replace API Platform's defaults, so serializer, invalid-argument and optimistic-lock errors returned `500`. They now return the `4xx` in [Error Status Codes](/api/debugging#error-status-codes).
- [ ] If a database seeded by an earlier version has duplicate usernames, delete the extra rows. `user:create` and `UserFactory` used to ignore the unique validation and save a duplicate, and login then failed with a `500` ([#274](https://github.com/components-web-app/api-components-bundle/pull/274)).

**What changed, with no action needed:**

- On FrankenPHP worker mode or RoadRunner, use alpha.2 or later ([#209](https://github.com/components-web-app/api-components-bundle/pull/209)). `1.1.11` and `2.0.0-alpha.1` remembered a cleared file (`{ "file": null }`) in the worker after the request ended, so later publishes served by the same worker could delete their own files.
- A failed Mercure publish is logged instead of turning an already-saved write into a `500` ([#284](https://github.com/components-web-app/api-components-bundle/pull/284)).
- A missing source image skips its Imagine filter with a warning instead of failing the whole `GET` with a `500` ([#301](https://github.com/components-web-app/api-components-bundle/pull/301)). A non-image upload to a field with `imagineFilters` skips Imagine instead of erroring.
- The manifest lists a page's layout component groups ([#307](https://github.com/components-web-app/api-components-bundle/pull/307)), and is tagged per rendering depth instead of by every IRI it lists ([#244](https://github.com/components-web-app/api-components-bundle/pull/244)). Editing a component's content no longer purges any manifest, so manifests stay cached much longer. Before, a 44-resource manifest produced about 2.7 KB of `Surrogate-Key` header, more than Souin's 1500-byte batch. See [Resource manifests are tagged per page](/api/configuration#resource-manifests-are-tagged-per-page).
- `Expires` also lowers `s-maxage` and `max-age` ([#240](https://github.com/components-web-app/api-components-bundle/pull/240)). See [Scheduled Publication and Cache Lifetime](/api/configuration#scheduled-publication-and-cache-lifetime).
- An unknown username on the resend-verification routes returns `404`, where it returned a `500` leaking `Username not found`.
