This section is for back-end developers. It covers the Symfony side of a CWA site: the bundle, your component entities, users and security, fixtures and caching. For the Vue side, see the [Nuxt Module](/nuxt-module). If you're new to CWA, start with [Core Concepts](/core-concepts).

The API Components Bundle is the [Symfony](https://symfony.com){target="_blank"} backend of CWA. It wires together [API Platform](https://api-platform.com){target="_blank"}, [Doctrine ORM](https://www.doctrine-project.org/projects/orm.html){target="_blank"}, [LexikJWTAuthenticationBundle](https://github.com/lexik/LexikJWTAuthenticationBundle){target="_blank"} and [Mercure](https://mercure.rocks){target="_blank"}, and adds the resources a CWA site is built from: layouts, pages, routes, component groups and your own components.

## Core Resources

The bundle registers these resources for you. Core resources are served under the `/_/` prefix, components under `/component/`, and page data under `/page_data/`. These sit below whatever prefix your app mounts API Platform on — `/_api` in the CWA template, so the full path to layouts is `/_api/_/layouts`.

| Resource | Endpoint prefix | Purpose |
|----------|----------------|---------|
| Layout | `/_/layouts` | Outer page shell (header/footer) |
| Page | `/_/pages` | Individual pages with component groups |
| Route | `/_/routes` | URL → page/page data mapping |
| ComponentGroup | `/_/component_groups` | Named, ordered lists of components, each belonging to a layout, page or component |
| ComponentPosition | `/_/component_positions` | Place one component in a group and set its order |
| SiteConfigParameter | `/_/site_config_parameters` | Key–value site settings |
| CollaborationState | `/_/collaboration_states` | Admin only. The shared editing state of one field, see [Versions & Conflicts › Collaboration States](/api/versions-and-conflicts#collaboration-states) |
| Collection | `/component/collections` | Proxy to paginated resource lists |
| Form | `/component/forms` | Symfony form types via API |

Your own components extend `AbstractComponent` (see [Creating Components](/api/components/creating-components)), and your page data extends `AbstractPageData` (see [Page Data & Nested Pages](/api/dynamic-pages)). Every core resource except `SiteConfigParameter` and `CollaborationState` has `createdAt` and `modifiedAt`. Components and page data also have a version in `_metadata.version`; see [Versions & Conflicts](/api/versions-and-conflicts).

### Layout

| Field | Description |
|-------|-------------|
| `reference` | A unique name, such as `main` |
| `uiComponent` | The Vue layout component that renders it, such as `CwaLayoutPrimary` |
| `uiClassNames` | Style classes chosen in the admin |
| `componentGroups` | Its component groups |
| `pages` | The pages that use it. Read-only |

`search` matches `reference` and `uiComponent`.

### Page

| Field | Description |
|-------|-------------|
| `reference` | A unique name |
| `layout` | The layout it renders in. Required |
| `isTemplate` | Whether page data renders through it. Required |
| `uiComponent`, `uiClassNames` | The Vue page component, such as `CwaPagePrimaryPageTemplate`, and its style classes |
| `title`, `metaDescription` | Used for the page's SEO tags |
| `route` | The route that publishes it, if any |
| `parentPage`, `parentPageData` | Its parent in a nested hierarchy (see [Page Data & Nested Pages › Nested Pages](/api/dynamic-pages#nested-pages)) |
| `isReachableWithoutRoute` | Admin only. See [Public Pages Without a Route](/api/users/access-control#public-pages-without-a-route) |
| `componentGroups` | Its component groups |

`search` matches `title`, `reference` and `uiComponent`, and `isTemplate=true` or `false` filters. Page data has the same `title`, `metaDescription`, `route`, parent and `isReachableWithoutRoute` fields.

### Route

A route maps a path to one page or page data record. Its fields, generation, redirects and go-live dates are covered in [Routes](/api/routes).

### ComponentGroup

| Field | Description |
|-------|-------------|
| `reference` | A unique name. The fixture builder uses `{name}_{owner IRI}`, or `{name}_{locationReference}` for a shared group (see [Builder Reference › `locationReference` — Shared Groups](/api/data-fixtures/builder-reference#locationreference-shared-groups)) |
| `location` | The IRI of the layout, page or component the group was declared in |
| `layouts`, `pages`, `components` | Its owners. A draft of a published component given as an owner is stored as the published component |
| `componentPositions` | Its positions, in order |
| `allowedComponents` | Collection IRIs of the component types it accepts. `null` accepts every type except [explicit-allow-only](/api/components/annotations/explicit-allow-only) ones |
| `maxComponents` | The most components it holds. `null`, the default, is unlimited. See [Limiting How Many Components a Group Holds](/api/components/component-groups#limiting-how-many-components-a-group-holds) |

`GET` and `PATCH` on `/_/component_groups/{id}/order` read and set the order of its positions in one request. See [Reordering a group in one request](/api/components/component-groups#reordering-a-group-in-one-request).

To move a component between positions and page data properties in one request, see [Component Groups & Positions › Moving a Component](/api/components/component-groups#moving-a-component). To list where a component is used, see [Component Groups & Positions › Where a Component Is Used](/api/components/component-groups#where-a-component-is-used).

### ComponentPosition

| Field | Description |
|-------|-------------|
| `componentGroup` | The group it belongs to |
| `component` | The component it shows. It can't be a component whose subtree holds the group; see [A Component Can't Contain Itself](/api/components/component-groups#a-component-cant-contain-itself). Written with a draft of a published component, it stores the published component; see [Publishable › A Reference to a Draft Stores the Published Component](/api/components/annotations/publishable#a-reference-to-a-draft-stores-the-published-component). Absent for a caller who can't see drafts when the component isn't published yet; see [Positions Holding an Unpublished Component](/api/components/annotations/publishable#positions-holding-an-unpublished-component) |
| `sortValue` | Its order in the group, lowest first. Read-only: the server chooses it |
| `after`, `before` | Write-only. The IRI of a position in the same group to place this one after or before. See [Placing a position](/api/components/component-groups#placing-a-position-after-and-before) |
| `pageDataClass`, `pageDataProperty` | Set together to show the component held in a page data property instead. Admin only on read. See [Component Positions from PageData](/api/dynamic-pages#component-positions-from-pagedata) |

### SiteConfigParameter

A `key` (the identifier, such as `siteName`) and a JSON `value`. `GET /_/site_config_parameters` is public and returns up to 100 parameters, so the front end can read the site's settings. Reading one parameter by its key, and every write, needs `publishable.permission`. A write also purges every cached page; see [Purging Every Rendered Page](/api/http-caching#purging-every-rendered-page). The Nuxt module's admin edits them as site settings. A deploy can switch maintenance mode (`maintenanceModeEnabled`) with the [Console Commands › `maintenance`](/api/console-commands#maintenance) command.

### Length Limits

The bundle's text fields are `VARCHAR(255)` columns. A longer value is a **422**, with a violation on the field, before anything is written. These fields have the limit:

| Resource | Fields |
|----------|--------|
| Layout, Page, component | `uiComponent`. A page's is measured with the `CwaPage` prefix the API adds |
| Layout, Page, ComponentGroup | `reference` |
| Page, page data | `title`, `metaDescription` |
| ComponentGroup | `location` |
| ComponentPosition | `pageDataProperty`, `pageDataClass` |
| Route | `path`, `name` |
| SiteConfigParameter | `key` |
| Form | `formType` |
| Collection | `resourceIri` |
| User | `username`, `emailAddress`, `newEmailAddress` |

Editors are most likely to meet it on a page's `metaDescription`.

::callout{icon="i-heroicons-exclamation-triangle" color="warning"}
**SQLite doesn't enforce the length.** A local SQLite database saves a 300-character value that PostgreSQL and MySQL reject. Your own `string` columns need the same care: see [String Columns Need a Length Limit](/api/components/creating-components#string-columns-need-a-length-limit).
::
