Full YAML structure with every option, its type, and default value. Each block is explained on its own page; see [Where Each Block Is Explained](#where-each-block-is-explained).

Leave out any required field and the container fails to compile, with an error that names the missing key. The required fields are:

- `website_name`
- `user`, with `user.class_name`
- `publishable`, with `publishable.permission`
- `refresh_token`, with `handler_id`, `cookie_name`, `ttl` and `database_user_provider`
- `refresh_token.options.class`, but only when `handler_id` is the Doctrine storage handler (`silverback.api_components.refresh_token.storage.doctrine`). A custom handler doesn't need it.

Everything else has a default. That includes all of `user.email_verification`, which defaults to **off**: users start unverified, no verification email is sent, and unverified users can still sign in. Anything stricter needs a redirect target for its emails, so you have to opt in. If you turn on `verify_on_register` or `verify_on_change`, you must also set `email.default_redirect_path` or `email.redirect_path_query`, or the container won't compile.

::callout{icon="i-heroicons-exclamation-triangle" color="warning"}
`user.email_links` compiles without a value, but then every email that carries a link (password reset, verification, welcome, account enabled) is refused. Set `default_origin` or `allowed_origins`. See [Links in Emails](/api/users/user-emails#links-in-emails).
::

## Full Configuration

```yaml
silverback_api_components:

    # Required. Used in email subjects and templates.
    website_name: My CWA App

    # Table prefix for all bundle-managed tables. Default: '_acb_'
    table_prefix: '_acb_'

    # Key under which runtime metadata is nested in API responses. Default: '_metadata'
    metadata_key: '_metadata'

    # ─── User ────────────────────────────────────────────────────────────────
    user:
        # Required. Fully-qualified class name of your User entity.
        class_name: App\Entity\User

        email_verification:
            enabled: true
            # Whether new users start verified (false = must verify email)
            default_value: false
            # Send a verification email when a new user registers
            verify_on_register: true
            # Re-send verification when the user changes their email
            verify_on_change: true
            # Block login for unverified email addresses
            deny_unverified_login: true
            email:
                # Query param name carrying the redirect path (optional)
                redirect_path_query: ~
                # Path with {{ username }} and {{ token }} placeholders
                default_redirect_path: /verify-email/{{ username }}/{{ token }}
                subject: Please verify your email
            # Minimum seconds between verification emails (429 until then). Default: 300
            repeat_ttl_seconds: 300

        new_email_confirmation:
            email:
                redirect_path_query: ~
                default_redirect_path: /confirm-new-email/{{ username }}/{{ new_email }}/{{ token }}
                subject: Please confirm your new email address
            # Token validity in seconds. Default: 86400 (24 hours)
            request_timeout_seconds: 86400
            # Minimum seconds between confirmation emails (429 until then). Default: 300
            repeat_ttl_seconds: 300

        password_reset:
            email:
                redirect_path_query: ~
                default_redirect_path: /reset-password/{{ username }}/{{ token }}
                subject: Your password reset request
            # Minimum seconds between password reset emails only (429 until then).
            # Default: 86400 (24 hours)
            repeat_ttl_seconds: 86400
            # Reset token validity in seconds. Default: 3600
            request_timeout_seconds: 3600

        # Origin that links in user emails point to. Set one of these, or every
        # email carrying a link is refused. See User Emails.
        email_links:
            # scheme://host[:port]. Default: null
            default_origin: 'https://www.example.com'
            # Regexes, anchored by the bundle, that the request's Origin/Referer
            # may match to be used instead. Default: []
            allowed_origins: []

        emails:
            welcome:
                enabled: true
                subject: 'Welcome to {{ website_name }}'
            user_enabled:
                enabled: true
                subject: 'Your account has been enabled'
            username_changed:
                enabled: true
                subject: 'Your username has been updated'
            password_changed:
                enabled: true
                subject: 'Your password has been changed'

    # ─── Publishable ─────────────────────────────────────────────────────────
    publishable:
        # Symfony expression: who can read/write draft resources and publish
        permission: "is_granted('ROLE_ADMIN')"

    # ─── HTTP Cache Safety ───────────────────────────────────────────────────
    http_cache:
        # Resource classes whose GET responses are marked `private, no-store`
        # for authenticated users, so a shared cache never stores an admin's
        # draft view. Any Publishable resource is treated this way automatically,
        # in addition to this list. Default: [Route, ResourceManifest, ComponentPosition]
        personalised_resource_classes:
            - 'Silverback\ApiComponentsBundle\Entity\Core\Route'
            - 'Silverback\ApiComponentsBundle\ApiResource\ResourceManifest'
            - 'Silverback\ApiComponentsBundle\Entity\Core\ComponentPosition'
        # Resource classes whose anonymous GET responses have `s-maxage` and
        # `max-age` capped at the soonest future route go-live date.
        # Default: [Route, RoutableInterface, ResourceManifest]
        scheduled_expiry_resource_classes:
            - 'Silverback\ApiComponentsBundle\Entity\Core\Route'
            - 'Silverback\ApiComponentsBundle\Entity\Core\RoutableInterface'
            - 'Silverback\ApiComponentsBundle\ApiResource\ResourceManifest'
        # Resource classes whose writes also purge the `cwa-html` surrogate key,
        # dropping every cached page. List only leaf resources.
        # Default: [SiteConfigParameter]
        purge_rendered_html_classes:
            - 'Silverback\ApiComponentsBundle\Entity\Core\SiteConfigParameter'

    # ─── Built-in Components ─────────────────────────────────────────────────
    enabled_components:
        form: true        # The Form component (Symfony FormType → JSON)
        collection: true  # The Collection component (resource list proxy)

    # ─── Refresh Tokens ──────────────────────────────────────────────────────
    # Every key in this block except `options` is required — there are no defaults.
    refresh_token:
        # Service ID of the refresh token storage handler
        handler_id: silverback.api_components.refresh_token.storage.doctrine
        options:
            # Your RefreshToken entity class (see the template app's src/Entity/RefreshToken.php)
            class: App\Entity\RefreshToken
        # Must match the cookie name in lexik_jwt_authentication.set_cookies
        # and token_extractors.cookie.name.
        cookie_name: api_component
        # Token lifetime in seconds (the template uses 604800 = 1 week)
        ttl: 604800
        # The user provider alias used in security.yaml
        database_user_provider: database

    # ─── Mercure ─────────────────────────────────────────────────────────────
    mercure:
        # Name of the Mercure hub (if multiple hubs; null = default hub)
        hub_name: ~
        cookie:
            # SameSite attribute for the Mercure cookie. Default: 'strict'
            # (The cookie's name comes from the hub: __Secure-mercure_access_token for Mercure 1.0.)
            samesite: '%env(JWT_COOKIE_SAMESITE)%'
        # Scope subscriber JWT tokens to resources the current user can access.
        # Recommended in production. Default: false (all topics subscribed).
        secure_subscriptions: false

    # ─── Route Security ──────────────────────────────────────────────────────
    # URL pattern → Symfony security expression. Evaluated per-route.
    route_security:
        - { route: '/user-area*', security: "is_granted('ROLE_USER')" }
        - { route: '/admin*', security: "is_granted('ROLE_ADMIN')" }

    # Expression for who can read pages, page data and components that no live
    # Route reaches, and who can create pages and page data. Default: null (no gate)
    routable_security: "is_granted('ROLE_ADMIN')"

    # ─── Orphaned Resources ──────────────────────────────────────────────────
    # Emails sent by `scan-orphaned` when the orphans differ from the last
    # alert. See Orphaned Data.
    orphaned_resources:
        notify:
            # A list, or one comma-separated string so an env var can supply it.
            # Default: [] (no emails)
            recipients: '%env(ORPHANED_RESOURCES_NOTIFY_RECIPIENTS)%'
            # Front-end path of the admin page, linked on
            # user.email_links.default_origin. Default: '/_cwa/orphaned'
            admin_page_path: '/_cwa/orphaned'
            # Default: 'Orphaned resources changed on {{ website_name }}'
            subject: 'Orphaned resources changed on {{ website_name }}'

    # ─── Orphaned Files ──────────────────────────────────────────────────────
    # The orphaned files report. See Orphaned Data.
    orphaned_files:
        # Seconds since a file was last modified before it can be reported.
        # A file is stored before its row is saved, so a younger file may be
        # an upload in progress. Default: 3600
        minimum_age: 3600
        # Path prefixes never listed or reported on any scanned filesystem,
        # for anything else you store beside your uploads. The LiipImagine
        # cache prefix is always excluded. Default: []
        excluded_paths: []

    # ─── Imagine ─────────────────────────────────────────────────────────────
    # The memory budget for generating LiipImagine filters. See Uploadable →
    # Large Images and PHP Memory.
    imagine:
        # PHP memory_limit while a filter is generated, raised only for the
        # generation and restored after it. A filter estimated not to fit is
        # skipped and logged. A higher memory_limit is kept; null generates
        # under the current limit. Default: '320M'
        memory_limit: '320M'

    # ─── Uploadable ──────────────────────────────────────────────────────────
    # The Cache-Control written on stored files, on Google Cloud Storage and
    # S3 adapters only. A field overrides either value with `cacheControl:` or
    # `imagineCacheControl:` on its #[UploadableField]; `false` there writes
    # none. null here writes none. See Uploadable → Cache-Control on Stored Files.
    uploadable:
        cache_control:
            # For an uploaded file. A stored name is never reused, so it can be
            # immutable. Default: 'public, max-age=31536000, immutable'
            original: 'public, max-age=31536000, immutable'
            # For an imagine variant, which is written again at the same path
            # when its filter is generated again. Default: 'public, max-age=2592000'
            imagine: 'public, max-age=2592000'
        # The pixel limit of an #[UploadedImage] constraint that sets no
        # maxPixels, on upload and in the orphaned files report. 30 megapixels
        # fits the default imagine memory_limit with vips; use 20000000 with GD
        # or Imagick. A positive integer, or null for no limit.
        # Default: 30000000
        image_max_pixels: 30000000

    # ─── Fixtures ────────────────────────────────────────────────────────────
    # Where generate-fixtures stores uploaded files by content hash, and where
    # a scaffold's $cwa->asset() loads them from. Unset, generate-fixtures
    # writes readable copies beside the scaffold. Writing the block turns it
    # on; enabled: false turns it off. See Generating Fixtures → Keeping Files
    # in an Asset Store.
    fixtures:
        assets:
            # Default: false, or true once you write any other key here
            enabled: false
            # local (a folder) or flysystem (one of your filesystem adapters).
            # An %env()% value is allowed. Default: local
            store: local
            # The local store's folder. null is an assets/ folder beside the
            # scaffold class. Default: null
            path: null
            # The flysystem store's adapter alias. Required for flysystem.
            # Default: null
            adapter: null
            # The flysystem store's folder within the adapter. Default: ''
            prefix: ''
```

There is no `enabled` flag for the orphaned resources email: no recipients means no email. Literal addresses are checked when the container compiles; addresses from an environment variable are checked when an email is sent. See [Emailing When Orphans Change](/api/orphaned-data#emailing-when-orphans-change) for when it sends. The email covers orphaned resources only, not the [orphaned files report](/api/orphaned-data#orphaned-files).

`fixtures.assets` sets the fixture asset store. A `store` other than `local` or `flysystem`, or `flysystem` without an `adapter`, fails when the container compiles. A store from an environment variable is checked when a command uses it. *Since bundle 2.0.0-alpha.23 ([#466](https://github.com/components-web-app/api-components-bundle/pull/466)).*

`uploadable.image_max_pixels` is the pixel limit for every [`#[UploadedImage]`](/api/components/annotations/uploadable#capping-uploads-to-fit-the-budget) field that sets no `maxPixels` of its own. It applies to uploads and to the [invalid files check](/api/orphaned-data#how-invalid-files-are-checked). It must be a positive integer or `null`; anything else fails when the container compiles. *Since bundle 2.0.0-alpha.23 ([#456](https://github.com/components-web-app/api-components-bundle/pull/456)).*

## Environment Variables

This is the one list of variables the bundle's configuration reads. Set non-secret values in `.env` and secrets in `.env.local`, which is never committed, or in your deployment's secrets.

| Variable | Purpose |
|----------|---------|
| `APP_SECRET` | Symfony application secret. Secret |
| `DATABASE_URL` | Doctrine connection string, such as `postgresql://user:pass@localhost:5432/app?serverVersion=16&charset=utf8` |
| `JWT_SECRET_KEY` | Path to the private key PEM file, such as `%kernel.project_dir%/config/jwt/private.pem` |
| `JWT_PUBLIC_KEY` | Path to the public key PEM file, such as `%kernel.project_dir%/config/jwt/public.pem` |
| `JWT_PASSPHRASE` | Private key passphrase. Secret |
| `JWT_COOKIE_SAMESITE` | `SameSite` for the JWT cookie and, through `mercure.cookie.samesite`, the Mercure cookie (`strict`, `lax`, `none`). The template defaults it to `lax`, and its Kubernetes deploys set it from the CI variable `CWA_API_JWT_COOKIE_SAMESITE` |
| `MERCURE_URL` | Internal API → hub URL, used to publish. It must be reachable from the PHP container, such as `http://php.local/.well-known/mercure` |
| `MERCURE_PUBLIC_URL` | Browser → hub URL, used to subscribe, such as `https://www.example.com/.well-known/mercure` |
| `MERCURE_JWT_SECRET` | The key the API signs its Mercure tokens with. Secret |
| `MERCURE_PUBLISHER_JWT_KEY`, `MERCURE_SUBSCRIBER_JWT_KEY` | Read by the hub (Caddy), not Symfony, to verify tokens. With a shared HMAC key, both equal `MERCURE_JWT_SECRET`. The template sets all three from `CADDY_MERCURE_JWT_SECRET`. `MERCURE_PUBLISHER_JWT_ALG` and `MERCURE_SUBSCRIBER_JWT_ALG` set the algorithm. Secret |
| `MAILER_DSN` | Symfony Mailer transport, such as `smtp://user:pass@smtp.example.com:587` |

The template adds variables of its own, such as `EMAIL_LINK_DEFAULT_ORIGIN` for [`user.email_links.default_origin`](/api/users/user-emails#links-in-emails) and `MAILER_EMAIL` for the orphan alert. Its CI variables are listed in [CI/CD](/deployment/ci-cd).


## Services You Can Override

All ~320 bundle services have stable string IDs in the form `silverback.api_components.*`. Each service's FQCN is also registered as an alias, so you can decorate using either form in `config/services.yaml`:

```yaml
# config/services.yaml
services:
    App\YourCustomFilesystemProvider:
        decorates: Silverback\ApiComponentsBundle\Flysystem\FilesystemProvider

    # or equivalently using the stable string ID:
    App\YourCustomFilesystemProvider:
        decorates: silverback.api_components.flysystem.filesystem_provider
```

Commonly overridden services:

| Service ID | Purpose |
|------------|---------|
| `Silverback\ApiComponentsBundle\Flysystem\FilesystemProvider` | Custom storage adapter resolution |
| `Silverback\ApiComponentsBundle\Security\UserChecker` | Custom account checks on login |
| `silverback.security.jwt_manager` | JWT creation/parsing (decorates `lexik_jwt_authentication.jwt_manager`) |

The bundle does **not** own the login success/failure handlers — those are Lexik's (`lexik_jwt_authentication.handler.authentication_success` and `…_failure`) and are wired on the `login` firewall in `security.yaml` rather than decorated. See [Authentication → Security Configuration](/api/users/authentication#security-configuration).

The string IDs follow the class namespace: `Silverback\ApiComponentsBundle\Foo\BarBaz` → `silverback.api_components.foo.bar_baz`. Inspect `vendor/components-web-app/api-components-bundle/src/Resources/config/services.php` for the full list.
