The methods below are on the `CwaFixtureBuilder` that `build()` receives, and on the sub-builders they return. [Getting Started](/api/data-fixtures/getting-started) shows them together in a complete example, and [Writing a Scaffold](/api/data-fixtures/writing-a-scaffold) shows how to lay a scaffold out.

## The Builder API

### `layout()`

```php
$cwa->layout(string $ref, string $uiComponent, ?array $uiClassNames = null): LayoutBuilder
```

Creates (or retrieves if already registered) a Layout entity.

- `$ref` — the key used to reference this layout in `page()` calls. It is also stored as the Layout's `reference`.
- `$uiComponent` — the **suffix** of the Vue component name in `app/app/cwa/layouts/`. The builder prepends `CwaLayout` automatically: `'Primary'` → stores `CwaLayoutPrimary`.
- `$uiClassNames` — optional array of CSS class strings applied to the layout wrapper. These are the classes the admin can select from the "Style" picker (defined in your Nuxt component via `useCwaComponent` `styles` option).

Calling `layout()` twice with the same `$ref` returns the same `LayoutBuilder` — useful for adding groups across separate calls.

### `page()`

```php
$cwa->page(
    string $ref,
    string $uiComponent,
    string $layout,
    ?string $route = null,
    ?string $routeName = null,
    bool $isTemplate = false,
    ?\Closure $configure = null,
    ?array $uiClassNames = null
): PageBuilder
```

Creates a Page entity.

- `$ref` — key unique within this fixture, also stored as the Page's `reference`
- `$uiComponent` — the **suffix** of the Vue component name in `app/app/cwa/pages/`. The builder prepends `CwaPage` automatically: `'Blog'` → stores `CwaPageBlog`. A page written through the API is stored the same way.
- `$layout` — the `$ref` of a layout already registered in this builder
- `route` — creates an explicit Route at this path; omit to auto-generate from the page title
- `routeName` — a name for `getRoute()` retrieval after `flush()`
- `isTemplate: true` — marks the page as a template (no route is generated)
- `configure` — optional closure called immediately with the `PageBuilder`, for inline configuration
- `uiClassNames` — optional array of CSS class strings for the page wrapper (same "Style" field the admin selects)

The `configure` closure is equivalent to chaining on the returned builder, but keeps setup co-located with the call — useful when creating multiple pages or when you don't need to reference the builder later:

```php
// Using configure closure — inline, no variable needed
$cwa->page('home', 'PrimaryPageTemplate', layout: 'main', route: '/',
    configure: function (PageBuilder $builder) use ($hero): void {
        $builder->title('Home')
            ->group('hero')->add($hero);
    }
);

// Equivalent chained form
$cwa->page('home', 'PrimaryPageTemplate', layout: 'main', route: '/')
    ->title('Home')
    ->group('hero')->add($hero);
```

### `pageData()`

```php
$cwa->pageData(
    AbstractPageData $pageData,
    ?string $template = null,
    ?string $route = null,
    ?string $routeName = null,
    ?\Closure $configure = null
): PageDataBuilder
```

Wraps a `PageData` record (e.g. a blog article).

- `$template` — the `$ref` of the template page this data record uses
- `route` / `routeName` — same as `page()`
- `configure` — optional closure called immediately with the `PageDataBuilder`, same inline pattern as `page()`

### `component()`

```php
$cwa->component(AbstractComponent $component): ComponentBuilder
```

Registers a component entity with the builder. Returns a [`ComponentBuilder`](#componentbuilder-from-cwa-component) for adding child groups, a draft, and route or IRI links. A component that owns groups is saved with its groups, and any other component is saved with the positions (see [Flush Phases](#flush-phases)).

### `publish()`

```php
$cwa->publish(object $resource, ?\DateTimeInterface $at = null): object
```

Sets the publish date of a publishable component: now, or `$at` to schedule it. It returns the component, so you can write `$group->add($cwa->publish(new Hero()))`. It doesn't save the component. A class that isn't `#[Silverback\Publishable]` throws a `LogicException`. See [Publishing and Drafts](/api/data-fixtures/writing-a-scaffold#publishing-and-drafts).

*Since bundle 2.0.0-alpha.22 ([#453](https://github.com/components-web-app/api-components-bundle/pull/453)).*

### `persist()`

```php
$cwa->persist(object $entity): static
```

Explicitly persist any non-CWA entity (custom relations, settings, etc.). Walks owning-side associations and persists related objects recursively.

### `getRoute()`

```php
$cwa->getRoute(string $routeName): Route
```

Returns a named `Route` once routes exist: inside an [`afterRoutes()`](#afterroutes) callback, or after `flush()`. To set a component's route field, use [`linkRoute()`](#componentbuilder-from-cwa-component) instead.

Every route the builder creates or keeps can be named: by its `routeName:`, or by its own name. A route with a `route:` but no `routeName:` is named after its path (`/about/team` is `about-team`), and a generated one after its title's slug. A route an `--append` load kept is also found by the name its path gives, so a scaffold that names `about` still finds a saved `/about` route called `about-1`. See [References, Route Names and Paths](/api/data-fixtures/writing-a-scaffold#references-route-names-and-paths).

A name that this scaffold hasn't declared is looked up in the database, so you can reach a route that is already saved, such as one another scaffold created earlier in the same load. It throws a `LogicException` (`Named route "…" not found`) when no route has that name.

### `redirect()`

```php
$cwa->redirect(string $path, string $to, ?string $name = null): static
```

Declares a redirect from `$path` to the route named `$to`. It is created during `flush()`, straight after the page routes, so you don't need a `flush()` of your own first. See [Seeding Redirects](#seeding-redirects).

### `afterRoutes()`

```php
$cwa->afterRoutes(\Closure $callback): static
```

Registers a callback that runs once during the next `flush()`, after every route and redirect has been created and before any component position is. It receives the builder, so `getRoute()` works inside it.

To set a route field, use [`linkRoute()`](#componentbuilder-from-cwa-component), and to link a draft, use [`draft()`](#componentbuilder-from-cwa-component). Keep `afterRoutes()` for anything else that needs a route, such as a field your own code works out from it:

```php
$cwa->afterRoutes(function (CwaFixtureBuilder $cwa) use ($banner): void {
    $banner->ctaPath = $cwa->getRoute('about-us')->getPath(); // [!code focus]
});
```

A component in a group is still unsaved when the callback runs, and its position is created afterwards with the field already set.

### `flush()`

```php
$cwa->flush(): void
```

Triggers the full persistence sequence (see [Flush Phases](#flush-phases)). `AbstractCwaScaffold::load()` calls it after `build()`. Call it yourself again any time you register new entities or positions after an earlier call.

## Sub-builder APIs

### `LayoutBuilder` — from `$cwa->layout()`

```php
->uiClassNames(string ...$classes): self
->group(
    string $name,
    array $allow = [],
    ?\Closure $configure = null,
    ?string $locationReference = null
): GroupBuilder
```

`uiClassNames()` sets the CSS classes on the layout after construction — equivalent to passing `$uiClassNames` to `layout()` directly, but useful when chaining or configuring an already-retrieved builder:

```php
$cwa->layout('main', 'Primary')
    ->uiClassNames('bg-stone-900', 'text-white')
    ->group('nav', allow: [NavigationLink::class], locationReference: 'global-nav');
```

`group()` creates a `ComponentGroup` linked to this layout. `$allow` is an array of component class names to restrict what admins can add. Leave empty to allow all types.

### `PageBuilder` — from `$cwa->page()`

```php
->title(string $title): self
->metaDescription(string $description): self
->uiClassNames(string ...$classes): self
->liveAt(?\DateTimeImmutable $liveAt): self
->withoutRoute(): self
->reachableWithoutRoute(bool $reachable = true): self
->group(
    string $name,
    ?\Closure $configure = null,
    ?string $locationReference = null,
    array $allow = []
): GroupBuilder
->nested(\Closure $configure): self
->getRoute(): ?Route    // available after flush()
```

::callout{icon="i-heroicons-information-circle"}
A page group's `allow` is its **fourth** argument, not its second as on `LayoutBuilder` and `ComponentBuilder`, so pass it by name: `->group('primary', allow: [HtmlContent::class])`. Leave it out to allow every component type.
::

`liveAt()` sets the go-live date of the page's route: a future date schedules it, and `null` creates the route offline. See [Scheduled and Offline Routes](#scheduled-and-offline-routes).

`withoutRoute()` keeps a page that isn't a template without a route. Without it, a page with no `route:` gets one generated from its title. A page with no title gets no route either way. It only applies when you don't pass `route:`, and a template page never gets a route anyway:

```php
$cwa->page('services', 'PrimaryPage', layout: 'main')->withoutRoute(); // [!code focus]
```

A routeless page is useful as the parent of pages that do have routes. Give each child an explicit `route:`, because a child can't have one generated under a parent with no route (see [Route Generation Rules](#route-generation-rules)).

`reachableWithoutRoute()` makes a page without a route readable by visitors, for a page your app loads by IRI. See [Public Pages Without a Route](/api/users/access-control#public-pages-without-a-route).

`nested()` receives a `CwaFixtureBuilder` scoped to this page as parent. Anything you create in the closure becomes a child of the page. Pass one method per child, as in [Writing a Scaffold](/api/data-fixtures/writing-a-scaffold#one-method-per-layout-page-and-page-data):

```php
$page = $cwa->page('blog', uiComponent: 'Primary', layout: 'main', route: '/blog')
    ->title('Blog');

$page->nested($this->firstPostPageData(...)); // [!code focus]
$page->nested($this->secondPostPageData(...)); // [!code focus]
```

Each call adds a closure, and they run in order. A closure can call `nested()` on what it creates, and those closures run too, to any depth. `nested()` returns the builder.

::callout{icon="i-heroicons-exclamation-triangle" color="warning"}
**Up to bundle 2.0.0-alpha.21, a second `nested()` replaced the first**, `PageBuilder::nested()` returned `void`, and a `nested()` called inside a nested closure never ran. *Changed in bundle 2.0.0-alpha.22 ([#453](https://github.com/components-web-app/api-components-bundle/pull/453)).*
::

::callout{icon="i-heroicons-information-circle"}
`title` and `metaDescription` are `protected` on `AbstractPage`, so set them with `setTitle()` / `setMetaDescription()` — assigning `$entity->title` directly is a fatal error.
::

### `PageDataBuilder` — from `$cwa->pageData()`

```php
->nested(\Closure $configure): self
->onRoutesCreated(\Closure $cb): self
->liveAt(?\DateTimeImmutable $liveAt): self
->withoutRoute(): self
->linkRoute(string $property, string $routeName): self
->linkIri(string $property, string|int|array|null $key = null, ?string $page = null, ?string $layout = null, ?string $pageData = null, ?string $route = null): self
->getRoute(): ?Route
```

`nested()` works as it does on `PageBuilder`. `linkRoute()` and `linkIri()` work as they do on [`ComponentBuilder`](#componentbuilder-from-cwa-component), on a field of the page data.

`liveAt()` works as it does on `PageBuilder`. `withoutRoute()` creates the page data with no route at all. It only applies when you don't pass `route:`:

```php
$draft = new BlogArticleData();
$draft->setTitle('Coming Soon');
$cwa->pageData($draft, template: 'blog-template')->withoutRoute(); // [!code focus]
```

Without it, page data with no `route:` gets a generated one, if it has a title. Untitled page data with no `route:` gets no route, and is treated like `withoutRoute()` page data in an appended load.

::callout{icon="i-heroicons-exclamation-triangle" color="warning"}
**Routeless page data is only created in the same load as its template page or parent.** The builder has nothing to look it up by, so it can't tell whether the record already exists. When neither its template page nor its parent is being created in this load, it is skipped and counted as `unidentifiable`. That happens even on an empty database if the record has no `template:` and no parent. See [Appending to an Existing Site](/api/data-fixtures/appending#appending-to-an-existing-site).
::

`onRoutesCreated()` fires after all child routes have been created, in the same phase as [`afterRoutes()`](#afterroutes). The closure receives `array<PageBuilder>` of child page builders, useful for wiring nav links that target child URLs. Add each link to a group builder: its position is created later in the same `flush()`, so don't call `flush()` inside the callback.

```php
$navGroup = $cwa->layout('main', 'Primary')->group('nav');

$cwa->pageData($section, template: 'section-template')
    ->nested(function (CwaFixtureBuilder $child): void {
        $child->page('article-1', 'Article', layout: 'main')
            ->title('First Article');
    })
    ->onRoutesCreated(function (array $childBuilders) use ($navGroup): void {
        foreach ($childBuilders as $child) {
            $link = new NavigationLink();
            $link->route = $child->getRoute(); // [!code focus]
            $navGroup->add($link); // [!code focus]
        }
    });
```

When you know the child routes' names, `afterRoutes()` with `getRoute()` does the same job.

::callout{icon="i-heroicons-exclamation-triangle" color="warning"}
`onRoutesCreated()` only receives child **Page** builders. Child `pageData()` records created inside `->nested()` are tracked separately and never passed to the callback. Give them a `routeName:` and link to it with `linkRoute()` instead.
::

### `GroupBuilder` — from Any `->group()` Call

```php
->add(AbstractComponent $component, ?int $sort = null): self
->pageDataPosition(string $pageDataClass, string $propertyName, ?int $sort = null): self
```

`add()` creates a `ComponentPosition` pointing to the component. Sort values auto-increment by 10 unless specified.

`pageDataPosition()` creates a position bound to a field on a specific `PageData` class — used in template pages where a region renders a component held by the associated data record. `pageDataClass` must be the fully-qualified class name of an `AbstractPageData` subclass registered as an API Platform resource:

```php
$cwa->page('blog-template', 'BlogPageTemplate', layout: 'main', isTemplate: true)
    ->group('content')
        ->pageDataPosition(BlogArticleData::class, 'headline')  // renders BlogArticleData->headline component
        ->pageDataPosition(BlogArticleData::class, 'body');     // renders BlogArticleData->body component
```

### `ComponentBuilder` — from `$cwa->component()`

```php
->uiComponent(string $suffix): self
->uiClassNames(string ...$classes): self
->group(string $name, array $allow = [], ...): GroupBuilder
->draft(AbstractComponent $draft): self
->linkRoute(string $property, string $routeName): self
->linkIri(
    string $property,
    string|int|array|null $key = null,
    ?string $page = null,
    ?string $layout = null,
    ?string $pageData = null,
    ?string $route = null
): self
```

`uiComponent()` sets an alternative UI template for this component. The builder computes the full component name from the entity's class name: on a `NavigationLink` entity, `->uiComponent('Button')` stores `CwaComponentNavigationLinkUiButton`.

`uiClassNames()` sets style classes — the same classes the admin can select from the "Style" picker.

`group()` is for components that contain other components (e.g. a carousel with slide children):

```php
$carousel = new Carousel();
$cwa->component($carousel)
    ->group('slides', allow: [Slide::class])
        ->add(new Slide())
        ->add(new Slide());

// Setting an alt UI and style on a component
$link = new NavigationLink();
$cwa->component($link)
    ->uiComponent('Button')
    ->uiClassNames('rounded', 'shadow-lg');
```

`draft()` links a draft to this published component. Don't add the draft to a group. A component that isn't publishable throws a `LogicException`.

`linkRoute()` sets a field to the route with that name, once the routes exist. `linkIri()` writes the IRI of a page or layout (by reference), page data (by its route's name) or route (by name) into a field, or into a key of an array field. Pass exactly one target. Both are explained in [Linking Routes and IRIs](/api/data-fixtures/writing-a-scaffold#linking-routes-and-iris).

```php
$cwa->component($link)->linkRoute('route', routeName: 'about'); // [!code focus]
$cwa->component($articleList)->linkIri('defaultQueryParameters', key: 'parentPage', page: 'blog'); // [!code focus]
```

*`draft()`, `linkRoute()` and `linkIri()` since bundle 2.0.0-alpha.22 ([#453](https://github.com/components-web-app/api-components-bundle/pull/453)).*

## `locationReference` — Shared Groups

By default a `ComponentGroup` reference is `"{groupName}_{ownerIri}"`. If `locationReference` is set, the reference becomes `"{groupName}_{locationReference}"` — stable across environments and shared across multiple owners.

This is how a single navigation group can serve multiple layouts:

```php
// Both layouts share the same ComponentGroup record
$cwa->layout('primary', 'Primary')
    ->group('nav', allow: [NavigationLink::class], locationReference: 'global-nav');

$cwa->layout('minimal', 'Minimal')
    ->group('nav', allow: [NavigationLink::class], locationReference: 'global-nav');
```

The Vue `<CwaComponentGroup>` with the matching `locationReference` prop renders this shared group.

## Flush Phases

Every `flush()` call runs the full sequence. Each phase is idempotent: already-processed entities, nested closures and callbacks are tracked and skipped, so only work added since the previous `flush()` is done. The underlying `EntityManager::flush()` is only called when something changed.

| Phase | What happens |
|-------|-------------|
| **1** | Look up existing layouts, pages, page data and groups (see [Appending to an Existing Site](/api/data-fixtures/appending#appending-to-an-existing-site)), then persist the ones that are missing. When the scaffold has no `nested()` closure, components that own groups are persisted here too, with their groups. Skips already-persisted entities. Calls `EntityManager::flush()` only if anything new was added. |
| **nested** | Run the `nested()` closures, to any depth, and persist what they declare. When the scaffold has a `nested()` closure, components that own groups are persisted here. Each closure runs at most once. |
| **3** | Create explicit routes, and call `RouteGenerator::create()` for entities that don't yet have a route, in parent-before-child order. Apply `liveAt()`. Then create the `redirect()` routes. |
| **3.5** | Apply `linkRoute()` and `linkIri()`. Fire `onRoutesCreated` callbacks, then `afterRoutes()` callbacks, each at most once. Then apply any links the callbacks added. |
| **4** | Create `ComponentPosition` entities for all registered group builders, and persist their components. Then persist components registered with `component()` that own no groups, and drafts. |

So you can call `flush()` as many times as you like. Anything that references a route belongs in `linkRoute()`, `linkIri()` or `afterRoutes()`, which run between phases 3 and 4 of the same `flush()`.

::callout{icon="i-heroicons-exclamation-triangle" color="warning"}
**Since bundle 2.0.0-alpha.22, components registered with `component()` are saved later.** One that owns no groups, and a draft, is saved with the positions, not in phase 1. One that owns groups is saved after the `nested()` closures whenever the scaffold has one. So such a component may have no id yet in a `nested()` closure or an `afterRoutes()` callback. Set route and IRI fields with `linkRoute()` and `linkIri()`, which don't depend on that order ([#453](https://github.com/components-web-app/api-components-bundle/pull/453)).
::

## Route Generation Rules

| Situation | Result |
|-----------|--------|
| `route: '/path'` explicit | Creates a Route at that path |
| `routeName: 'name'` | Also names the route for `getRoute('name')` |
| `isTemplate: true`, no `route` | No Route created |
| No `route`, has `title` | `RouteGenerator` slugifies the title → `/my-title` |
| `pageData()` inside `->nested()`, no route | `RouteGenerator` → `/parent-path/slug` |
| `page()`/`pageData()` inside `->nested()` of a parent that gets no route (e.g. `isTemplate: true`), no `route` | `flush()` throws `UnroutedParentException`. Pass an explicit `route:` |
| No `route`, no `title`, top-level or nested | No Route created, as with `withoutRoute()`. A child that would have a route generated under it throws `UnroutedParentException`. *Since bundle 2.0.0-alpha.19; before, it got `/unnamed-page`* |
| No `route`, a `title` that gives no slug (only punctuation, say) | `flush()` fails with the route generator's 422 (`A title is needed to generate a route.`) |
| `page()` or `pageData()` with `->withoutRoute()`, no `route` | No Route created |
| `route: '/path'` whose path or route name another route already has | No Route created. The page or page data is created without one, and the summary counts the route as skipped (`path in use`) |

### Scheduled and Offline Routes

A route the builder creates is live from the moment it is saved. Call `liveAt()` on the page or page data builder to change that:

```php
$cwa->page('launch', 'PrimaryPage', layout: 'main', route: '/launch')
    ->liveAt(new \DateTimeImmutable('2026-11-01 09:00')); // [!code focus]

$cwa->page('draft', 'PrimaryPage', layout: 'main', route: '/draft')
    ->liveAt(null); // [!code focus]
```

A future date schedules the route and `null` keeps it offline. The rules are in [Scheduling and Taking Routes Offline](/api/routes#scheduling-and-taking-routes-offline). The date is only applied to a route created in this load. An appended load never changes the `liveAt` of a route that already exists.

## Seeding Redirects

A redirect is a `Route` whose `redirect` property points at another `Route`. How the API and the Nuxt module follow it is covered in [Routes → Redirects](/api/routes#redirects).

Declare redirects with `$cwa->redirect()`. The target is a **route name**: the `routeName:` of a page or page data, the name of any route the builder creates or keeps, or the name of an earlier redirect.

```php
public function build(CwaFixtureBuilder $cwa): void
{
    $cwa->page('about', 'PrimaryPage', layout: 'main', route: '/about-us', routeName: 'about-us');

    $cwa->redirect('/about', to: 'about-us'); // [!code focus]
}
```

The builder creates redirects during `flush()`, straight after the page routes, so they need no `flush()` of their own. Each one gets `createdAt`/`modifiedAt` like any other route.

- **`name`** defaults to the path with its slashes turned into hyphens: `/about` becomes `about`, and `/blog/old-post` becomes `blog-old-post`. If another route already has that name, the redirect gets the first free suffix: `about-1`, then `about-2`. Pass `name:` to choose it yourself.
- **Chains** (`/a` → `/b` → `/c`) work, and the front end resolves to the last route in the chain. Declare the hop nearest the page first and point the next one at its name:

  ```php
  $cwa->redirect('/about', to: 'about-us', name: 'about-redirect');
  $cwa->redirect('/company', to: 'about-redirect');
  ```

- **An existing path is left alone.** If a route already has the redirect's path, the builder keeps that route and creates nothing, even when the existing route is not a redirect. A second load therefore doesn't duplicate or change it.

::callout{icon="i-heroicons-exclamation-triangle" color="warning"}
**`to` must name a route the builder knows about, or one in the database.** Any other name makes `flush()` throw a `LogicException` that names the redirect's path and lists the routes of the load.

**A `name:` you pass is not suffixed.** If a route created in the same load already has it, `flush()` throws a `LogicException` (`The redirect "…" cannot be named "…"`), even when the redirect's path already exists. If a saved route has it, the redirect isn't created and the summary counts it as skipped (`name in use`).
::

Outside a scaffold, for example in your own service, `RouteGeneratorInterface::createRedirect(string $fromPath, Route $targetRoute): Route` builds the same kind of route for you to persist. It makes the name unique but not the path, and it doesn't look anything up first.
