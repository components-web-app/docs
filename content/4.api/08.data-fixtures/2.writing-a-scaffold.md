A scaffold is easiest to read when it looks like the site map: one method for each layout, page and page data. [`generate-fixtures`](/api/data-fixtures/generating-fixtures) writes scaffolds in this style, so a generated scaffold and a hand-written one look the same.

The worked example is the bundle's [`SiteScaffold.php`](https://github.com/components-web-app/api-components-bundle/blob/main/features/fixtures/scaffolds/SiteScaffold.php). The bundle's tests load it and generate it again, and the generated file must match it exactly. The examples below follow it, with the template's entity names.

*Since bundle 2.0.0-alpha.22 ([#453](https://github.com/components-web-app/api-components-bundle/pull/453)).*

## One Method per Layout, Page and Page Data

`build()` only calls methods. Each layout, top-level page and top-level page data has a private method of its own, and redirects go last:

```php
class SiteScaffold extends AbstractCwaScaffold
{
    private NavigationLink $contactLink;

    public function build(CwaFixtureBuilder $cwa): void
    {
        $this->mainLayout($cwa);
        $this->homePage($cwa);
        $this->aboutPage($cwa);
        $this->redirects($cwa);
    }

    private function mainLayout(CwaFixtureBuilder $cwa): void
    {
        $homeLink = new NavigationLink();
        $homeLink->label = 'Home';
        $cwa->component($homeLink)->linkRoute('route', routeName: 'home');

        $this->contactLink = new NavigationLink();
        $this->contactLink->label = 'Contact us';
        $cwa->component($this->contactLink)->linkRoute('route', routeName: 'about');

        $cwa->layout('main', uiComponent: 'Primary')
            ->group('header', allow: [NavigationLink::class])
            ->add($homeLink)
            ->add($this->contactLink);
    }

    private function homePage(CwaFixtureBuilder $cwa): void
    {
        $welcomeHtmlContent = new HtmlContent();
        $welcomeHtmlContent->html = '<h2>Welcome</h2><p>Build pages from components.</p>';
        $cwa->publish($welcomeHtmlContent);

        $page = $cwa->page('home', uiComponent: 'Primary', layout: 'main', route: '/', routeName: 'home')
            ->title('Home');

        $page->group('primary')
            ->add($welcomeHtmlContent);
    }

    private function aboutPage(CwaFixtureBuilder $cwa): void
    {
        $page = $cwa->page('about', uiComponent: 'Primary', layout: 'main', route: '/about')
            ->title('About');

        $page->nested($this->aboutTeamPage(...)); // [!code focus]
    }

    private function aboutTeamPage(CwaFixtureBuilder $cwa): void
    {
        $cwa->page('about-team', uiComponent: 'Primary', layout: 'main', route: '/about/team', routeName: 'team')
            ->title('Team')
            ->group('primary')
            ->add($this->contactLink);
    }

    private function redirects(CwaFixtureBuilder $cwa): void
    {
        $cwa->redirect('/our-team', to: 'team');
    }
}
```

The rules it follows:

- **A child page or page data has its own method**, passed to its parent's `nested()`: `$page->nested($this->aboutTeamPage(...));`. Each `nested()` call adds one more closure, so a parent with three children has three `nested()` lines.
- **Components are named variables**, such as `$homeLink` or `$welcomeHtmlContent`, declared in the method that places them.
- **A component used in more than one method is a typed property.** `$this->contactLink` is in the layout's header and on the team page. Assign it in the method that runs first. The methods `build()` calls run before any `nested()` closure, so a property set in `mainLayout()` is ready in `aboutTeamPage()`.
- **Name the `uiComponent:` argument.** The bare suffix, `'Primary'`, doesn't say what it is.

Small private factory methods are welcome when they make a scaffold shorter, for example one link builder for the whole header:

```php
private function navigationLink(CwaFixtureBuilder $cwa, string $label, string $routeName): NavigationLink
{
    $link = new NavigationLink();
    $link->label = $label;
    $cwa->component($link)->linkRoute('route', routeName: $routeName);

    return $link;
}
```

## Publishing and Drafts

A publishable component that you only create is a draft. Visitors don't see drafts. Publish it with `$cwa->publish()`:

```php
$cwa->publish($welcomeHtmlContent); // published when the fixtures load
$cwa->publish($saleBanner, at: new \DateTimeImmutable('2027-01-15 09:00')); // scheduled
```

`publish()` sets the publish date in the type the entity maps, and returns the component. It doesn't save it, so you still add the component to a group. A class that isn't `#[Silverback\Publishable]` throws a `LogicException`.

To give a published component a pending draft, create the draft and link it with `draft()`:

```php
$welcomeDraft = new HtmlContent();
$welcomeDraft->html = '<h2>Welcome to version 2</h2>';
$cwa->component($welcomeHtmlContent)->draft($welcomeDraft); // [!code focus]
```

Don't add the draft to a group. The builder links it to the published component at once and saves it after the positions.

## Linking Routes and IRIs

`linkRoute()` sets a field that holds a `Route`, by the route's name or by the page's builder. It works on a component builder and on a page data builder:

```php
$cwa->component($homeLink)->linkRoute('route', routeName: 'home');
$cwa->component($aboutLink)->linkRoute('route', page: $about); // $about = $cwa->page('about', …)
```

Pass exactly one of `routeName:` and `page:`. `page:` takes a page or page data builder and links its route, whatever the route is called. *`page:` since bundle 2.0.0-alpha.23 ([#474](https://github.com/components-web-app/api-components-bundle/pull/474)); see [A Builder as the Target](/api/data-fixtures/builder-reference#a-builder-as-the-target).*

The builder sets the field once the routes exist, so you don't need an [`afterRoutes()`](/api/data-fixtures/builder-reference#afterroutes) callback for it. A name that no route in the load or the database has throws a `LogicException` that names the component's class and field, and lists the routes of the load.

`linkIri()` writes the IRI of a page, layout, page data or route into a string field, or into a key of an array field. Use it instead of copying an IRI into the scaffold, because the id in an IRI changes every time the fixtures load:

```php
$cwa->component($articleList)
    ->linkIri('defaultQueryParameters', key: 'parentPage', page: 'blog'); // [!code focus]
```

Name exactly one target:

| Argument | Names |
|----------|-------|
| `page:` | A page by its reference, or its `PageBuilder` |
| `layout:` | A layout by its reference |
| `pageData:` | Page data by the **name of its route**, or its `PageDataBuilder` |
| `route:` | A route by its name, or the route of a `PageBuilder` or `PageDataBuilder` |

Leave out `key:` to set the whole field. A `key:` writes the IRI at that key, and a list such as `key: ['filters', 0, 'page']` follows a path into nested arrays, creating missing keys.

Both are applied after the routes are created and before the positions. You can also call them inside `afterRoutes()` and `onRoutesCreated()`. In an `--append` load they are ignored for a skipped component and for page data that was kept or skipped.

::callout{icon="i-heroicons-exclamation-triangle" color="warning"}
**A component that owns groups is saved before its `linkRoute()` is applied**, because its groups need an owner. The field it links must allow `null`, or the load fails.
::

## References, Route Names and Paths

A scaffold names things in three ways, and they aren't interchangeable:

| Name | Set by | Example | Used by |
|------|--------|---------|---------|
| **Reference** | The first argument of `layout()` and `page()` | `'about-team'` | `page(layout: …)`, `pageData(template: …)`, `linkIri(page:, layout:)`, and an `--append` load's lookup |
| **Route name** | `routeName:`, or derived from the path | `'team'` | `getRoute()`, `redirect(to:)`, `redirectTo()`, `linkRoute()`, `linkIri(route:, pageData:)` |
| **Route path** | `route:`, or generated from the title | `'/about/team'` | The URL visitors open, and `redirect()`'s first argument |

A route you give a path but no `routeName:` is named after its path, with the slashes turned into hyphens: `/about` is `about`, `/about/team` is `about-team`, and `/` is `root`. A generated route is named after the slug of its title. Every route the builder creates or keeps can be named in `getRoute()`, `redirect(to:)`, `redirectTo()` and `linkRoute()`, by `routeName:` or by its own name. Except in `getRoute()` and `redirectTo()`, you can pass the page or page data builder instead of a name (see [A Builder as the Target](/api/data-fixtures/builder-reference#a-builder-as-the-target)).

## Go-live Dates and Publish Dates

These are two different dates:

- **`liveAt()` is the route's go-live date.** It decides when the URL works. Without it, a route the builder creates is live as soon as it's saved. See [Scheduled and Offline Routes](/api/data-fixtures/builder-reference#scheduled-and-offline-routes).
- **`publish()` sets a component's publish date.** It decides whether visitors see that component or nothing. See [Publishable](/api/components/annotations/publishable).

A page on a live route still hides its unpublished components. And when the API sets `routable_security`, as the template does, a published component that is only on a scheduled route can't be read until the route goes live (see [Public Access Follows Routes](/api/users/access-control#public-access-follows-routes)).

## Components on Page Data

A component you set on a page data field is saved with the page data. You don't need `component()` or `persist()` for it:

```php
$pageData = new ConferenceData();
$pageData->setTitle('CWA Conference');
$pageData->component = new Hero(); // saved with the page data // [!code focus]

$cwa->pageData($pageData, template: 'conference', route: '/cwa-conference');
```

Set the field before you call `pageData()`.

## Asset File Names

The name of a file in `assets/` doesn't matter. When the fixtures load, the file is stored under a new name: its own name in lower case, with a token added, such as `hero-3f9a2b7c.jpg`. The extension comes from the file's content. Nothing refers to the stored name, so rename an asset whenever you like. See [Seeding Uploadable Files](/api/data-fixtures/seeding-content#seeding-uploadable-files).
