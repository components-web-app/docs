title: Upgrading the Module
description: What changes between @cwa/nuxt releases, and the steps to take for each one, newest first.
---

Each section below covers one release of `@cwa/nuxt`, newest first. Work through every section between your current version and the one you're moving to, oldest first. The other pages in this section describe the current release only.

The full list of changes, including fixes that need no action, is in the module's [`CHANGELOG.md`](https://github.com/components-web-app/cwa-nuxt-module/blob/main/CHANGELOG.md) and on its [GitHub releases](https://github.com/components-web-app/cwa-nuxt-module/releases). Several releases need a matching API bundle release; its own steps are in [Upgrading the Bundle](/api/upgrading). If you use the components-web-app template, [Upgrading the Template](/deployment/upgrading-the-template) pins each module release with the matching bundle.

## 2.0.0-alpha.10

Released 2026-10-10. The template pins it, with bundle `2.0.0-alpha.13`, from [template 2.0.0-alpha.22](/deployment/upgrading-the-template#_200-alpha22).

**Do this:**

- [ ] **Update api-components-bundle to `2.0.0-alpha.13` or later in the same deploy.** Every immediate publish from the admin now sends `"publishedAt": "now"`, and an older bundle rejects it because it isn't a date, so publishing fails. See [Upgrading the Bundle → 2.0.0-alpha.13](/api/upgrading#_200-alpha13).
- [ ] Optional: bind the new `srcset` on your image components, with a `sizes` of your own. See [Images & Media → Responsive images](/nuxt-module/component-helpers/images-and-uploads#responsive-images).

**What changed:**

- **Immediate publishing uses the API's clock** ([#381](https://github.com/components-web-app/cwa-nuxt-module/issues/381), [98659370](https://github.com/components-web-app/cwa-nuxt-module/commit/98659370)). The manager's **Publish** button, **Publish now**, a **Schedule** whose time has already passed, and adding a component published straight away all send the string `"now"` instead of the browser's time. A future schedule still sends the date you picked. Before, a browser whose clock was ahead of the server saved the publish as a draft scheduled a moment ahead. See [Scheduling a Publish](/core-concepts/admin-panel#scheduling-a-publish).
- **`srcset` on the file composables** ([#377](https://github.com/components-web-app/cwa-nuxt-module/issues/377), [797a8ff1](https://github.com/components-web-app/cwa-nuxt-module/commit/797a8ff1)). `useCwaFile`, `withFile()` and `useCwaFileField` return a `srcset` built from the field's sized variants.

## 2.0.0-alpha.9

Released 2026-10-10. The template pins it from [template 2.0.0-alpha.20](/deployment/upgrading-the-template#_200-alpha20).

**Do this:**

- [ ] To see invalid files in the admin, update api-components-bundle to `2.0.0-alpha.11` or later. An older bundle sends no `invalidFiles`, so the section stays empty. Nothing else breaks. See [Upgrading the Bundle → 2.0.0-alpha.11](/api/upgrading#_200-alpha11).

**What changed:**

- **Invalid files on the orphaned files page** ([#376](https://github.com/components-web-app/cwa-nuxt-module/issues/376), [09450e77](https://github.com/components-web-app/cwa-nuxt-module/commit/09450e77)). `/_cwa/orphaned` lists files in use that break their upload field's current rules, and the settings notice counts them. See [Orphaned files](/core-concepts/admin-panel#orphaned-files).
- **The Info tab's delete button names the version** ([#371](https://github.com/components-web-app/cwa-nuxt-module/issues/371), [fd3b4d97](https://github.com/components-web-app/cwa-nuxt-module/commit/fd3b4d97)): **Delete Draft** or **Delete Live** for a publishable component. See [Deleting a component](/core-concepts/admin-panel#deleting-a-component).
- The other changes are fixes that need no action: Move up / Move down when a group is on screen twice, and a failed background re-fetch keeping the loaded data.

## 2.0.0-alpha.8

Released 2026-10-08. The template pins it, with bundle `2.0.0-alpha.9`, from [template 2.0.0-alpha.15](/deployment/upgrading-the-template#_200-alpha15).

**Do this:**

- [ ] Update api-components-bundle to `2.0.0-alpha.9` or later, and run its migration. The **Public without a route** toggle reads and writes the bundle's new `isReachableWithoutRoute` property. See [Upgrading the Bundle → 2.0.0-alpha.9](/api/upgrading#_200-alpha9).

**What changed:**

- **Public without a route** ([#369](https://github.com/components-web-app/cwa-nuxt-module/issues/369), [5a919456](https://github.com/components-web-app/cwa-nuxt-module/commit/5a919456)). Page and page data settings have a toggle that makes a page without a route readable by visitors, for a page your app [loads by IRI](/nuxt-module/module-setup#load-a-cwa-page-by-iri). See [Visibility](/core-concepts/admin-panel#visibility) and [Public Pages Without a Route](/api/users-and-security#public-pages-without-a-route).

## 2.0.0-alpha.7

Released 2026-10-06.

**What changed:**

- **Visitors get the dynamic position fixes from alpha.5** ([#368](https://github.com/components-web-app/cwa-nuxt-module/issues/368), [60c9635c](https://github.com/components-web-app/cwa-nuxt-module/commit/60c9635c)). The module now recognises a dynamic position by `_metadata.isDynamicPosition`, because the API sends `pageDataProperty` only to admins. On alpha.5 and alpha.6, three fixes worked only for signed-in admins: no flash of the previous page's dynamic component after navigating between page-data pages, each depth of a shared template page rendering its own dynamic components, and the live re-fetch of dynamic positions after a page-data update. Visitors kept the old component until the next navigation.

## 2.0.0-alpha.5

Released 2026-10-05.

**What changed:**

- **Dynamic positions** ([#368](https://github.com/components-web-app/cwa-nuxt-module/issues/368), [05f4611e](https://github.com/components-web-app/cwa-nuxt-module/commit/05f4611e), [3938a1f3](https://github.com/components-web-app/cwa-nuxt-module/commit/3938a1f3)). Navigating between page-data pages no longer shows the previous page's dynamic component, a template page shared at two depths renders each depth's own dynamic components, and a page-data update that changes which component a property holds re-fetches the on-screen dynamic positions. Up to alpha.4, the old component stayed until the next navigation. Visitors get these from alpha.7, above. See [Real-Time Updates](/nuxt-module/component-helpers/real-time-updates#no-front-end-code-needed).

## Before 2.0.0-alpha.1

Edge builds before [`26f06f8d`](https://github.com/components-web-app/cwa-nuxt-module/commit/26f06f8d) ([#324](https://github.com/components-web-app/cwa-nuxt-module/issues/324)) counted an anonymous visitor's private 404 for an unpublished component in the page's cache headers, so a page that placed a draft component was never cached. Every tagged release has the fix. See [Page Caching](/nuxt-module/page-caching).
