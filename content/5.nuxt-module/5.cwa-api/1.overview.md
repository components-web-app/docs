`useCwa()` returns the singleton `Cwa` instance injected by the module plugin. These docs follow one convention for reaching it:

- **In templates**, use `$cwa`. It is available in every template without any import or declaration.
- **In `<script setup>` and composables**, call `useCwa()` and name the variable `cwa`.

```vue
<script setup lang="ts">
const cwa = useCwa()
const siteName = computed(() => cwa.siteConfig.config.siteName)
</script>

<template>
  <UserMenu v-if="$cwa.auth.signedIn.value" />
</template>
```

Both names refer to the same object. Some return values are also named `$cwa`, such as the one from `useCwaComponent()` and the context a [custom plugin](/nuxt-module/composables/component/use-cwa-component#writing-a-custom-plugin) receives, and the module's own source names its script variable `$cwa`. That works too, but don't declare a `$cwa` variable only to use it in the template: the global already covers that.

The `Cwa` class has six public sub-services, each documented on its own page:

| Property | Class | Purpose |
|----------|-------|---------|
| [`cwa.resources`](/nuxt-module/cwa-api/resources) | `Resources` | Read-only view of fetched resource state |
| [`cwa.resourcesManager`](/nuxt-module/cwa-api/resources-manager) | `ResourcesManager` | CRUD operations on resources |
| [`cwa.auth`](/nuxt-module/cwa-api/auth) | `Auth` | Authentication state and actions |
| [`cwa.forms`](/nuxt-module/cwa-api/forms) | `Forms` | Form view state and error access |
| [`cwa.admin`](/nuxt-module/cwa-api/admin) | `Admin` | Edit mode, component stack, admin panel |
| [`cwa.siteConfig`](/nuxt-module/cwa-api/site-config) | `SiteConfig` | Site-wide settings from the API |
| `cwa.orphanedResources` | `OrphanedResources` | The API's [orphaned resource report](/api/console-commands#orphaned-resource-report): `fetchReport()`, `requestScan()` and `deleteOrphans({ iris })` or `deleteOrphans({ all: true })`, which calls [`POST /_/orphaned_resources/delete`](/api/console-commands#deleting-orphans) and returns its `deleted` and `rejected` lists. `2.0.0-alpha.4` adds the file report: `fetchFileReport()`, `requestFileScan()` and `deleteOrphanedFiles({ paths })` or `deleteOrphanedFiles({ all: true })`. From `2.0.0-alpha.9` the file report's type has `invalidFiles`, each with `resource`, `field`, `adapter`, `path` and `violations`, which bundle `2.0.0-alpha.11` and later send. It backs the admin's [Orphaned Resources](/core-concepts/admin-panel#orphaned-resources) page. Admin only; added in `@cwa/nuxt` `2.0.0-alpha.3` |

## Top-Level Methods on `cwa`

These are lower-level fetch primitives. Most application code uses the composables instead.

```ts
// Fetch a specific resource by IRI
cwa.fetchResource({ path: '/component/titles/018e-...', isPrimary: false })

// Fetch the route manifest for a given Vue Router route
cwa.fetchRoute(route)

// Generic fetch (used internally)
cwa.fetch(event)

// Clear the primary fetch state, so page and layout resolve to nothing
// (the route middleware does this for `cwa: { disabled: true }` pages)
cwa.clearPrimaryFetch()

// Get the API Platform documentation (for component metadata)
await cwa.getApiDocumentation()
await cwa.getComponentMetadata(refresh, includePosition)

// Access the resolved API URL
cwa.apiUrlBase   // string

// Access the module's nuxt.config registrations
cwa.resourcesConfig    // the cwa.resources: {} config object
cwa.layoutsConfig      // the cwa.layouts: {} config object
cwa.pagesConfig        // the cwa.pages: {} config object
cwa.pageDataConfig     // the cwa.pageData: {} config object
```

## Common Patterns

### Auth-conditional rendering

`signedIn` can be rendered on the server, but `user`, `roles` and `isAdmin` need `<ClientOnly>`. See [Reading Auth State](/nuxt-module/authentication#reading-auth-state).

### Accessing the current page title

```ts
const pageTitle = computed(() =>
    cwa.resources.pageData.value?.data?.title
    ?? cwa.resources.page.value?.data?.title
    ?? ''
)
```

### Checking load state before rendering

```ts
const isReady = computed(() =>
    !cwa.resources.isLoading.value && !!cwa.resources.page.value?.data
)
```
