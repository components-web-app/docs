The CWA layer ships complete auth pages for every standard authentication flow. They work immediately after installation. [Authentication](/nuxt-module/authentication) explains each flow and its composable.

## Provided Pages

| Route | Component | Composable |
|-------|-----------|------------|
| `/login` | `<CwaAuthLoginPage>` | `useLogin()` |
| `/forgot-password` | `<CwaAuthForgotPasswordPage>` | `useForgotPassword()` |
| `/reset-password/[username]/[token]` | `<CwaAuthResetPasswordPage>` | `useResetPassword()` |
| `/verify-email/[username]/[token]` | — (auto-verifies on mount) | `useVerifyEmail()` |
| `/confirm-new-email/[username]/[newEmail]/[token]` | — (auto-confirms on mount) | `useVerifyEmail()` |

## Overriding a Page

Create the same path in `app/pages/` and your file wins over the layer's. Build it with the page's composable from the table above so it keeps the same API wiring, and set `cwa: { disabled: true }` in `definePageMeta`. [Customising the Login Page](/nuxt-module/authentication#customising-the-login-page) has a full example and explains why the flag is required and `layout` isn't.
