The CWA admin panel is shipped as part of the layer and requires no setup. It becomes accessible at `/_cwa` for any user with `ROLE_ADMIN`.

## Admin Routes

This is the complete list of admin routes. [The Admin Panel](/core-concepts/admin-panel) tours what an editor does with them.

| Route | Purpose |
|-------|---------|
| `/_cwa` | Redirects to `/_cwa/pages` |
| `/_cwa/pages` | Browse and create page records; assign each a layout and page template |
| `/_cwa/pages/[iri]` | Page settings: SEO title and description, layout, **Page UI** (`uiComponent`), style and parent, with **Routes** and **Info** tabs |
| `/_cwa/layouts` | Browse and create layout records |
| `/_cwa/layouts/[iri]` | Edit a layout: its reference, **Layout UI** (`uiComponent`) and style |
| `/_cwa/routes` | Manage routes: paths, redirects and the route tree |
| `/_cwa/routes/[iri]` | A page's or page data record's routes: path, redirects and visibility (live, scheduled or not live; see [Visibility](/core-concepts/admin-panel#visibility)) |
| `/_cwa/data` | Lists the page data types (blog, products, events…) |
| `/_cwa/data/[type]` | List and create records of one page data type |
| `/_cwa/data/[type]/[iri]` | Edit one page data record |
| `/_cwa/users` | List and create user accounts |
| `/_cwa/users/[iri]` | Edit an individual user and their roles. A pending email change shows **Resend email verification** (disabled with a countdown while throttled) and **Cancel change**, which clears the pending address so its emailed link stops working |
| `/_cwa/settings` | Site config: name, SEO defaults, robots, sitemap, maintenance mode, and the orphaned resources scan |
| `/_cwa/orphaned` | The last orphaned resource report: view and delete orphaned components, positions and groups. Opened from site settings, which can also start a scan. See [Orphaned Resources](/nuxt-module/cwa-layer/maintenance#orphaned-resources). Its **Files** report lists orphaned, unknown, missing and invalid files; see [Orphaned files](/nuxt-module/cwa-layer/maintenance#orphaned-files) |

The layer also registers `/_cwa/[cwaPage0]`, which isn't an admin page. It renders a CWA resource by its IRI, for links built with [`getInternalResourceLink`](/nuxt-module/composables/utilities/use-cwa-resource-route).

All `/_cwa` routes are client-only (SSR disabled). Every admin page under `/_cwa` uses the layer's `cwa-admin` route middleware, set on the `/_cwa` parent page and inherited by each admin page: a signed-out visitor is sent to `/login?redirect=…` and returned after sign-in, and a signed-in non-admin is sent to `/`. Signing out while on an admin route sends you back to `/`. To guard your own admin-only pages, use the same middleware — see [Protecting Pages](/nuxt-module/authentication#protecting-pages).

## Edit Mode

When an admin visits a content page, an edit bar appears at the top of the page (rendered by `<CwaAdminHeader>`). Clicking "Edit" toggles edit mode:

```ts
const cwa = useCwa()

cwa.admin.isEditing        // whether edit mode is active (a reactive boolean, not a ref)
cwa.admin.toggleEdit()     // open/close edit mode
```

In edit mode, every rendered component gains a selection overlay. Clicking a component opens its resource manager panel (`<CwaAdminResourceManager>`).

## The Resource Manager

The resource manager is a panel that slides in when a component is selected. It shows tabs for editing the component's data fields. The standard tabs (resource info, UI styles, publish, ordering) ship with the Nuxt module. Custom tabs are added using `useCwaResourceManagerTab`.

### Custom Manager Tab

Create a Vue component in `app/app/cwa/components/[ComponentName]/admin/[TabName].vue`. Use `useCwaResourceManagerTab` to register it:

```vue
<!-- app/app/cwa/components/Title/admin/SEO.vue -->
<template>
    <div class="p-4 space-y-4">
        <CwaUiFormLabelWrapper label="Meta Title">
            <CwaUiFormInput
                v-model="metaTitleModel"
                placeholder="Override page title for search engines"
            />
        </CwaUiFormLabelWrapper>
    </div>
</template>

<script setup lang="ts">
import { useCwaResourceManagerTab, useCwaResourceModel } from '#imports'

const { exposeMeta, iri } = useCwaResourceManagerTab({ name: 'SEO', order: 10 }) // [!code focus]

const { model: metaTitleModel } = useCwaResourceModel<string>(iri, 'metaTitle')

defineExpose(exposeMeta) // [!code focus]
</script>
```

::callout{icon="i-heroicons-exclamation-triangle" color="warning"}
`defineExpose(exposeMeta)` is required — without it the tab has no name and won't be ordered. The composable also returns the currently-selected `iri`, so the tab needs no `iri` prop of its own.
::

The tab appears in the resource manager whenever a `Title` component is selected.

## `cwa.admin` API

Edit mode, the selection stack and the navigation guard are controlled through `cwa.admin`. Its members are listed in [`cwa.admin`](/nuxt-module/cwa-api/admin).

## Navigation Guard

While edit mode is on, the module blocks programmatic navigation, `<NuxtLink>` clicks included, so an edit in progress isn't lost. [`cwa.admin` → Navigation Guard](/nuxt-module/cwa-api/admin#navigation-guard) covers what is blocked, the `?cwa_force=true` bypass and `setNavigationGuardDisabled()`.

Navigating away while a component is being added opens a dialog asking whether to discard it. See [`cwa.admin` → Navigation Guard](/nuxt-module/cwa-api/admin#navigation-guard).
