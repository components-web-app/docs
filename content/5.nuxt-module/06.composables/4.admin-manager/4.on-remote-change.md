`onRemoteChange` calls a handler when another admin saves a change to a resource. It's for components that keep their own state, such as an editor that holds its text outside the store, and need to know that the stored copy moved under them. The module already shows the change in place (see [Real-Time Updates › Co-Editing in the Admin](/nuxt-module/component-helpers/real-time-updates#co-editing-in-the-admin)), so most components need nothing.

```ts
import { onRemoteChange, useCwaResourceManagerTab } from '#imports'

const { exposeMeta, iri } = useCwaResourceManagerTab({ name: 'Content' })

onRemoteChange(iri, ({ changedFields, accept }) => { // [!code focus]
  if (changedFields.includes('html')) { // [!code focus]
    accept() // [!code focus]
  } // [!code focus]
}) // [!code focus]

defineExpose(exposeMeta)
```

## Signature

```ts
onRemoteChange(
  iri: MaybeRefOrGetter<string | undefined>,
  handler: (event: RemoteChangeEvent) => void
): () => void
```

`iri` can be a string, a ref or a getter, so the handler follows the selected resource. It returns a function that stops listening. Called inside a component's `setup`, it stops by itself when the component unmounts.

## The Event

| Property | Type | Description |
|----------|------|-------------|
| `resource` | `CwaResource` | The resource as the other admin saved it |
| `changedFields` | `string[]` | Top-level properties whose value differs from the copy you had. `@id`, `@context` and `_metadata` are never listed |
| `user` | `{ id: string } \| undefined` | The IRI of the user who saved it, from `_metadata.lastWrite.userId`. There's no name |
| `accept` | `() => void` | Chooses **Use theirs** for every control on this resource that's waiting for a choice. It does nothing once a newer change has arrived |

## When It's Called

- Only for a signed-in admin, in the browser, while co-editing is on. Visitors, the server render and an app with `cwa.realtime.enabled: false` never call it.
- Only for someone else's save. Your own saves coming back over Mercure, and a re-fetch after a reconnect that changed nothing, don't call it.
- For the draft and the live version alike: a handler on a draft's IRI hears a change to its live version, and the other way round.
- Not for a delete. The module deselects a removed component itself.

::callout{icon="i-heroicons-information-circle"}
**The change is already in the store when the handler runs**, except for a control that's waiting for **Use theirs / Keep mine**: that control keeps the admin's value until they choose. Call `accept()` only when your component can't offer the choice itself.
::
