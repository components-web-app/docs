The module doesn't ship a rich-text editor. The template has one, `app/app/components/TipTapHtmlEditor.vue`, built on [TipTap](https://tiptap.dev). Its `HtmlContent` component shows the editor to admins in edit mode, and the HTML through [`v-cwa-html`](/nuxt-module/component-helpers/html-content) to everyone else. This page covers the editor; [HTML Content](/nuxt-module/component-helpers/html-content) covers rendering the HTML.

## Loading an Editor Lazily

A rich-text component often shows an editor to admins, such as TipTap. Import the editor with `defineAsyncComponent`, not statically. A static import puts the editor into the preloads of every page with body text, for anonymous visitors too. In the template, that was about 424 KB of TipTap and ProseMirror (135 KB gzipped).

```vue
<template>
  <article>
    <TipTapHtmlEditor v-if="$cwa.admin.isEditing" :model="resourceModel" :iri="iri" />
    <div v-else ref="container" v-cwa-html="content" class="prose" />
  </article>
</template>

<script setup lang="ts">
import { defineAsyncComponent } from 'vue'

// Fetched only when an admin starts editing.
const TipTapHtmlEditor = defineAsyncComponent(() => import('~/components/TipTapHtmlEditor.vue')) // [!code focus]
// ...
</script>
```

Anywhere else that only needs the editor's type, use `import type`. A value import keeps the editor in the dev bundle.

```ts
import type TipTapHtmlEditor from '~/components/TipTapHtmlEditor.vue'

const editorComponent = ref<typeof TipTapHtmlEditor | undefined>()
```

Nuxt still adds a `prefetch` hint for the async chunk, so browsers may download it in the background. The template removes that hint with a `build:manifest` hook in `nuxt.config.ts`. It filters the editor out of each chunk's `dynamicImports`. The editor still loads on demand when it is first shown.

```ts
// nuxt.config.ts
const isEditorSource = (id: string) => id.endsWith('components/TipTapHtmlEditor.vue')

export default defineNuxtConfig({
  modules: [
    (_options, nuxt) => {
      nuxt.hook('build:manifest', (manifest) => {
        for (const chunk of Object.values(manifest)) {
          chunk.dynamicImports = chunk.dynamicImports?.filter(id => !isEditorSource(id))
        }
      })
    },
  ],
})
```

The module already keeps its own admin UI out of visitors' prefetch hints. It can't see your editor, because the editor is app code, so keep this hook.

## Choosing the Editor's Buttons

The template's `app/app/components/TipTapHtmlEditor.vue` shows a menu of formatting buttons: H1, H2, Bold, Italic, Underline, Link and Bullet List. Every button shows by default. Pass the `config` prop to hide some of them for one field.

For example, a short description that allows only bold, italic and links:

```vue
<TipTapHtmlEditor
  v-if="$cwa.admin.isEditing"
  :model="resourceModel"
  :iri="iri"
  :config="{ h1: false, h2: false, underline: false, bulletList: false }"
/>
```

The keys are `h1`, `h2`, `bold`, `italic`, `underline`, `link` and `bulletList`. Set a key to `false` to hide that button. The prop is typed, so a misspelt key fails the type check. A project whose copy of the file has no `config` prop can copy the current file from the template.

H1, H2 and Bullet List also appear in the menu shown on an empty line. That menu is hidden when all three are off.

::callout{icon="i-heroicons-exclamation-triangle" color="warning"}
**Hiding a button doesn't stop the style.** The editor still has every extension, so pasted content and keyboard shortcuts (such as Ctrl+U, or Cmd+U on a Mac, for underline) still apply it. `config` only changes the menu. To forbid a style, remove its extension from the editor, or clean the HTML on the API.
::

## Editing Together

The editor takes the HTML field's [`useCwaResourceModel`](/nuxt-module/composables/admin-manager/use-cwa-resource-model) as `:model`, and the component's IRI as `:iri`. With them, it works with other admins like the kit fields do:

- **Who's in the field.** Another admin with the editor in focus outlines it in their colour, with their name above it (`<CwaUiFieldPresence>`).
- **Their carets.** Each admin's caret and selection show in their colour while they're in the field. The editor sends them with [`useCwaRealtime`](/nuxt-module/composables/admin-manager/use-cwa-realtime).
- **Their saves.** Another admin's save is applied in place: only the changed part is replaced, so your caret stays where it was, and **Undo** doesn't undo their change.
- **Crossing changes.** If they save while you have typing that isn't saved, **Use theirs / Keep mine** shows below the editor (`<CwaUiRemoteChangeConflict>`).

How an editor of your own does the same is in [`useCwaResourceModel` › Your Own Field Editor](/nuxt-module/composables/admin-manager/use-cwa-resource-model#your-own-field-editor).

### Typing at the Same Time

The template's editor keeps one admin's typing at a time: when two admins type in the same field at once, one of them gets **Use theirs / Keep mine**. The module's playground has an editor that merges their typing instead, with [Yjs](https://yjs.dev):

- Two admins typing in the same field see each other's keystrokes as they type, with live carets.
- **Undo** only undoes your own typing.
- Each window saves its own typing, so **Publish** includes it. One window also saves the merged text.
- A change saved from outside the editor, such as from another tab of the manager panel, is applied into the shared text for everyone.
- The shared Yjs state for each field is kept in the API, so an admin who opens the field later starts from it (see [API › Versions & Conflicts › Collaboration States](/api/versions-and-conflicts#collaboration-states)).

It needs api-components-bundle `2.0.0-alpha.37` or later, which stores the Yjs state. With an older bundle, the editor logs a warning and starts from the saved HTML.

To use it, copy these files from the module's `playground/app/` into your `app/app/`, with their `.spec.ts` files if you run the playground's tests:

- `components/TipTapHtmlEditor.vue` and `components/TipTap/BubbleMenuButton.vue`
- `tiptap/co-editing.ts`, `y-sync.ts`, `y-seed.ts`, `y-session.ts`, `y-state.ts` and `y-cursors.ts`

Add the packages, with `@tiptap/extension-collaboration` on the same version as your other TipTap packages:

```bash
pnpm add yjs @tiptap/extension-collaboration @tiptap/y-tiptap
```

Then pass the editor the name of the field it edits, as `field`:

```vue
<TipTapHtmlEditor
  v-if="$cwa.admin.isEditing"
  :model="resourceModel"
  :iri="iri"
  field="html"
/>
```

Load the editor lazily, as in [Loading an Editor Lazily](#loading-an-editor-lazily), so Yjs never reaches visitors.

::callout{icon="i-heroicons-exclamation-triangle" color="warning"}
**The playground's editor has no `config` prop.** It shows every button. If your fields hide buttons with [`config`](#choosing-the-editors-buttons), carry that prop over from your current editor.
::

::callout{icon="i-heroicons-information-circle"}
**Known limits:**
- An editor that isn't selected shows no one's caret.
- Nothing stops the stored Yjs state growing past the API's limit for it: 8,388,608 base64 characters, about 6 MiB of Yjs data.
- If the window that saves the merged text has typing it hasn't sent when an outside save arrives, that admin gets **Use theirs / Keep mine** instead of a merge.
::
