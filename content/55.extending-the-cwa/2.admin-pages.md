An extension can add pages to the admin, such as a list of orders with a dialog for each one. They sit in the extension's own area under `/_cwa`, beside the built-in pages, in the same layout, behind the same sign-in check. This page adds an orders list and an order dialog, built from the parts the built-in lists use.

## Registering an Admin Page

Each entry in `adminPages` is one page:

```ts
// cwa-shop/module.ts, in register({ … })
label: 'Shop', // [!code focus]
description: 'Orders, refunds and sales reports', // [!code focus]
icon: 'lucide:shopping-cart', // [!code focus]
adminPages: [
  {
    path: 'orders', // [!code focus]
    label: 'Orders', // [!code focus]
    file: resolve('./admin/orders.vue'), // [!code focus]
    item: resolve('./admin/order.vue'), // [!code focus]
  },
  { path: 'reports', label: 'Reports', file: resolve('./admin/reports.vue'), role: 'ROLE_SHOP_ACCOUNTS' },
],
```

| Option | Required | What it does |
|--------|----------|--------------|
| `path` | Yes | The page's path in the extension's area: `orders` is `/_cwa/shop/orders`. It can have more than one segment |
| `label` | Yes | The page's tab in the area |
| `file` | Yes | An absolute path to the page's Vue file |
| `item` | No | An absolute path to a dialog for one item, opened over the list at `/_cwa/shop/orders/<iri>`. See [The Item Dialog](#the-item-dialog) |
| `role` | No | The role a user needs to open the page. Default `ROLE_ADMIN`, which a content admin with only `ROLE_CMS_ADMIN` doesn't have |

The extension's own `label` names its area and its entry on the Extensions page, where its `description` and `icon` show too (see [Registering an Extension › The Module File](/extending-the-cwa/registering-an-extension#the-module-file)).

## The Extension's Area

An extension with admin pages gets one area, at `/_cwa/<segment>`. The segment is the prefix in kebab-case: `Shop` is `/_cwa/shop`, and `SilverbackShop` is `/_cwa/silverback-shop`.

- The area's heading is the extension's `label`, and its pages are tabs below it, in the order `adminPages` lists them. A user sees only the tabs whose role they have.
- `/_cwa/shop` opens the first tab the user can open, so link to the area or to one of its pages.
- Each page's route is named `_cwa-` followed by the segment and the page's path, with `/` turned into `-`: `orders` is `_cwa-shop-orders`, and its item dialog is `_cwa-shop-orders-iri`.

::callout{icon="i-heroicons-exclamation-triangle" color="warning"}
**The area can't have a built-in admin page's name.** `account`, `data`, `extensions`, `index`, `layouts`, `orphaned`, `pages`, `routes`, `settings` and `users` are taken, so an extension with the prefix `Users` fails the build. Two extensions whose prefixes give the same segment fail it too.
::

Like every page under `/_cwa`, an extension's admin pages render only in the browser.

### Linking to an Admin Page

`cwaAdminRoute(segment, page, iri?)` returns the route to one of an area's pages, or with an `iri` to its item dialog. Use it for links between pages, and from the site to the admin:

```vue
<NuxtLink :to="cwaAdminRoute('shop', 'orders')">All orders</NuxtLink>
<NuxtLink :to="cwaAdminRoute('shop', 'orders', order['@id'])">Open this order</NuxtLink>
```

In development it throws when the area has no such page, or the page has no item dialog, so a renamed page shows up straight away.

### Who Can Open It

A signed-out visitor is sent to `/login` and back after signing in. A signed-in user without the page's role is sent to `/`. A user who has the role of any of the extension's pages gets the admin header, and its menu's **Extensions** link, even when it's their only admin role.

`role` must start with `ROLE_` and can't be `ROLE_USER`, which every signed-in user has. A role the user reaches through the role hierarchy counts, because `/me` lists every role a user reaches. See [Admin Roles › The Role Hierarchy](/api/users/admin-roles#the-role-hierarchy).

A role other than `ROLE_ADMIN` appears in the admin's user dialog as a toggle, named after the labels of the pages that need it, so a user admin can grant it (see [CWA Layer › Admin Panel › Admin Routes](/nuxt-module/cwa-layer/admin-panel#admin-routes)).

::callout{icon="i-heroicons-shield-check"}
The role only decides who sees the page. The API decides what they can read and change, so secure the extension's resources in its Symfony bundle too.
::

### The Extensions Page

`/_cwa/extensions` lists the extensions the user can open, each with its `icon`, `label` and `description`, linking to its area. The header menu links to it as **Extensions**, under General, for any user who has the role of an extension page. An extension with no admin pages is listed too, without a link, for users with `ROLE_ADMIN`.

## The List Page

`<CwaAdminList>` is the built-in lists' page: a heading, the search and sort row, the list with its loading, empty and error states, pages of 20, and the outlet the item dialog opens in. You give it the endpoint and render each row:

```vue
<!-- cwa-shop/admin/orders.vue -->
<template>
  <CwaAdminList
    title="Orders"
    fetch-url="/shop/orders"
    noun="orders"
    :columns="columns"
    :order-options="orderOptions"
    search-label="Search orders"
  >
    <template #item="{ data, link }"> <!-- [!code focus] -->
      <CwaAdminListRow :to="link" :title="data.number" :sub="data.customerEmail"> <!-- [!code focus] -->
        <CwaAdminListCell>
          <CwaUiBadge :tone="data.state === 'paid' ? 'success' : 'neutral'">
            {{ data.state }}
          </CwaUiBadge>
        </CwaAdminListCell>
        <CwaAdminListCell align="end">
          {{ data.total }}
        </CwaAdminListCell>
      </CwaAdminListRow>
    </template>
  </CwaAdminList>
</template>

<script setup lang="ts">
const columns = [
  { label: 'Order' },
  { label: 'State', width: '8rem' },
  { label: 'Total', width: '7rem', align: 'end' as const },
]
const orderOptions = [
  { label: 'Newest first', value: { createdAt: 'desc' } },
  { label: 'Highest total', value: { total: 'desc' } },
]

</script>
```

The extension names the routes for you: the list page is `_cwa-` plus the segment and its path (`_cwa-shop-orders`), and its item dialog is that name plus `-iri`. The list builds each row's `link` from them, and gives the item dialog its route key, so an extension's admin pages need no `definePageMeta` for routing.

| Prop | Required | What it does |
|------|----------|--------------|
| `title` | Yes | The page heading and the browser tab's title |
| `fetch-url` | Yes | The collection endpoint to list |
| `noun` | Yes | The plural used in the count and the empty and error messages, such as "No orders match these filters." |
| `columns` | Yes | One `{ label, width?, align?, labelHidden? }` per column. The first takes the remaining width; `align: 'end'` lines up numbers on the right |
| `order-options` | Yes | The sort choices. Each `value` is sent as `order[<field>]=<direction>`; the first is the default |
| `search-label` | Yes | The search field's label. What's typed is sent as `search=` |
| `create-noun` | No | Adds a create button (and one on the empty list) that opens the item dialog at `add`. Leave it out for records that aren't created in the admin, such as orders |

The list sends the page's query to `fetch-url`, so the API's collection needs filters for `search`, the `order` fields and anything else you add. The slots are:

| Slot | What goes in it |
|------|-----------------|
| `item` | One row, given `data` (the resource), `rawData` and `link` (the item dialog's route) |
| `filters` | More filters beside the search, bound to the page's query |
| `notice` | A notice above the list |
| `empty` | What an empty list shows, in place of the create button |

### Filters

A filter is a field bound to the page's query with [`useQueryBoundModel`](/nuxt-module/composables/utilities/use-query-bound-model). Every query parameter except `page`, `perPage` and `order` is sent to the API and counts as a filter, so the list offers to clear it when nothing matches:

```vue
<template #filters>
  <CwaUiMultiSelect
    v-model="states"
    label="State"
    label-hidden
    placeholder="Any state"
    search-placeholder="Search states"
    :options="stateOptions"
  />
</template>

<script setup lang="ts">
const stateOptions = ['awaiting_payment', 'paid', 'cancelled', 'refunded'].map(state => ({ label: state, value: state }))
const { model: stateModel } = useQueryBoundModel('state[]', { defaultValue: [] })
const states = computed({
  get: () => (stateModel.value ?? []) as string[],
  set: (value: string[]) => { stateModel.value = value },
})
</script>
```

### Rows

| Component | Props |
|-----------|-------|
| `<CwaAdminListRow>` | `title` (required), `to` (the row's link, usually `link`), `sub` (a second line), `dim`. With `actions`, it shows an edit button, and a view button when `view` is set; `name` labels them. The default slot holds its `<CwaAdminListCell>`s |
| `<CwaAdminListCell>` | One cell after the title. `align="end"` for numbers |

The row's title takes the first column, so give `columns` one entry more than the row has cells.

## The Item Dialog

The `item` file opens over the list when a row is clicked, at `/_cwa/shop/orders/<iri>`. `useCwaAdminItem` loads the resource from the route, as the built-in dialogs do, and `<CwaUiDialog>` lays it out:

```vue
<!-- cwa-shop/admin/order.vue -->
<template>
  <CwaUiDialog
    v-if="localResourceData || isLoading || loadFailed"
    placement="right"
    :title="localResourceData?.number ?? 'Order'"
    :tabs="tabs"
    :loading="isLoading"
    :load-failed="loadFailed"
    noun="order"
    @close="$emit('close')"
    @retry="loadResource()"
  >
    <template #details>
      <CwaUiFormSection title="Order">
        <CwaUiDetailList :items="summary" />
      </CwaUiFormSection>
      <CwaUiFormSection title="Lines">
        <CwaUiDataTable label="Order lines" :columns="lineColumns" :rows="localResourceData?.lines ?? []" />
      </CwaUiFormSection>
      <CwaUiFormSection v-if="localResourceData?.state === 'paid'" title="Refund">
        <CwaUiButton label="Refund" tone="danger" :loading="actionRunning" @click="refund" />
      </CwaUiFormSection>
    </template>
    <template #info>
      <CwaAdminResourceId :iri="localResourceData?.['@id']" />
    </template>
  </CwaUiDialog>
</template>

<script setup lang="ts">
const emit = defineEmits<{ close: [], reload: [] }>()

const { localResourceData, isLoading, loadFailed, loadResource, runAction, actionRunning } = useCwaAdminItem({ // [!code focus]
  createEndpoint: '/shop/orders', // [!code focus]
  emit, // [!code focus]
  resourceType: 'Order', // [!code focus]
  defaultResource: () => ({}), // [!code focus]
}) // [!code focus]

const tabs = [{ key: 'details', label: 'Details' }, { key: 'info', label: 'Info' }]
const lineColumns = [
  { key: 'title', label: 'Item' },
  { key: 'quantity', label: 'Qty', align: 'end' as const },
  { key: 'total', label: 'Total', align: 'end' as const },
]
const summary = computed(() => [
  { label: 'State', value: localResourceData.value?.state },
  { label: 'Email', value: localResourceData.value?.customerEmail },
  { label: 'Total', value: localResourceData.value?.total },
])

function refund() {
  const iri = localResourceData.value?.['@id']
  return iri && runAction({
    endpoint: `${iri}/refund`,
    confirm: { title: 'Refund this order?', go: 'Refund', tone: 'danger' },
    success: 'Order refunded',
  })
}
</script>
```

The dialog emits `close` to go back to the list and `reload` to refresh it. Each entry in `tabs` names a slot.

### `useCwaAdminItem`

It takes the options of the built-in dialogs' item composable:

| Option | Required | What it does |
|--------|----------|--------------|
| `createEndpoint` | Yes | Where a new item is posted, when the dialog is opened at `add` |
| `emit` | Yes | The dialog's `emit`, with `close` and `reload` |
| `defaultResource` | Yes | The fields a new item starts with |
| `resourceType` | No | The resource's type |

It returns the loaded resource and its state: `localResourceData` (the dialog's copy), `resource` (the stored one), `isLoading`, `loadFailed`, `loadResource()` to load it again, `saveResource()` and `deleteResource()` for an editable item, `form` for the dialog's fields (see [Editing an Item](#editing-an-item)), plus `runAction` and `actionRunning`.

### Running an Action

An action is a request that does something to the item, such as a refund. `runAction()` sends it, and only then reloads the item and the list:

| Field | What it does |
|-------|--------------|
| `endpoint` | Where the request goes |
| `method` | `POST` (default) or `PATCH` |
| `body` | The request body, if any |
| `confirm` | Ask first, with the admin's confirm dialog: `title`, `go` (the button), `tone` (`danger` or `accent`), and optionally `description` |
| `success` | A notice shown when the request succeeds |

It returns `true` when the request succeeded (an empty `204` counts), and `false` when the admin cancelled the confirm or the request failed. A failure shows no success notice and reloads nothing; the API's error appears as an error notice in the admin header, which stays until it's dismissed. The header shows for content and user admins, and for a user with the role of any extension admin page, so an admin with only the extension's role sees it too. `actionRunning` is `true` while an action runs, and a second action started meanwhile is ignored, so bind it to the button's `loading`.

## Editing an Item

For a dialog that edits its item, pass `useCwaAdminItem`'s `form` to `<CwaUiDialog>` and save on its `save` event. A kit field inside the dialog then binds with `field="<property>"`, and the dialog's Save, its count of unsaved changes and its discard prompt cover every field, as in the built-in dialogs:

```vue
<!-- cwa-shop/admin/payment-method.vue -->
<template>
  <CwaUiDialog
    v-if="localResourceData || isLoading || loadFailed"
    placement="right"
    :title="localResourceData?.name ?? 'Payment method'"
    :tabs="tabs"
    :form="form"
    :loading="isLoading"
    :load-failed="loadFailed"
    noun="payment method"
    @close="$emit('close')"
    @retry="loadResource()"
    @save="saveResource()"
  >
    <template #details>
      <CwaUiFormSection>
        <CwaUiInput field="name" label="Name" />
        <CwaUiToggle field="enabled" label="Enabled" />
      </CwaUiFormSection>
      <CwaUiFormSection title="Gateway">
        <CwaUiDescriptorFields :fields="gatewayFields" path="gatewayConfig" /> <!-- [!code focus] -->
      </CwaUiFormSection>
    </template>
  </CwaUiDialog>
</template>

<script setup lang="ts">
import type { CwaFieldDescriptor } from '@cwa/nuxt'

const emit = defineEmits<{ close: [], reload: [] }>()

const { localResourceData, isLoading, loadFailed, loadResource, saveResource, form } = useCwaAdminItem({
  createEndpoint: '/shop/payment_methods',
  emit,
  resourceType: 'PaymentMethod',
  defaultResource: () => ({ name: '', enabled: false, gatewayConfig: {} }),
})

const tabs = [{ key: 'details', label: 'Details' }]
const gatewayFields: CwaFieldDescriptor[] = [
  { name: 'vendor', label: 'Vendor name', type: 'string', required: true },
  { name: 'sandbox', label: 'Sandbox', type: 'bool' },
  { name: 'timeout', label: 'Timeout (seconds)', type: 'int' },
  { name: 'apiKey', label: 'API key', type: 'string', required: true, secret: true },
]
</script>
```

### Fields Inside an Object

A `field` can be a dotted path, such as `field="gatewayConfig.vendor"`, for a value inside an object property. Each path counts as its own unsaved change. Save sends only the values that changed, nested under their parent, so changing the vendor sends `{ "gatewayConfig": { "vendor": "…" } }` and leaves the object's other keys as they are. A `422` whose `propertyPath` is `gatewayConfig.vendor`, or a path below it, shows on that field. When several bound paths match, the longest one gets the message.

Once one dotted path under a property is bound, that whole property is compared key by key. A property with no dotted field bound is compared and sent whole.

### Fields From Descriptors

`<CwaUiDescriptorFields>` renders a field for each entry in `fields`, so the API can describe a form the dialog doesn't know in advance, such as each payment gateway's settings. Each entry is a `CwaFieldDescriptor`, a type exported from `@cwa/nuxt`:

| Key | What it does |
|-----|--------------|
| `name` | The property the field binds to. With `path`, it binds to `<path>.<name>` |
| `label` | The field's label |
| `type` | `string` (a `<CwaUiInput>`), `text` (a `<CwaUiTextarea>`), `int` (a `<CwaUiNumber>`) or `bool` (a `<CwaUiToggle>`) |
| `required` | A field that isn't required is marked optional. An optional `int` that's emptied saves `null` |
| `secret` | A `<CwaUiSecretInput>`, whatever the `type` |

Another `type` becomes a text input, and in development the console warns once for each unknown type. The component takes `path`, the object the fields sit in, and `disabled`, which disables every field. It renders only the fields, so put it inside a `<CwaUiFormSection>` in a dialog that has a `form`.

### Secret Fields

`<CwaUiSecretInput>` edits a value the admin can write but never read back, such as an API key. The API should return the field as `{ "set": true }` or `{ "set": false }`, never the value itself:

- When the value is set, the field shows **Set**, with **Replace** and **Remove**. **Replace** opens an empty input. **Remove** sends `null`, and the field shows **Will be removed** until it's saved. A field with `required` can't be removed, only replaced.
- When the value isn't set, the field is an empty input.
- The input has **Show value**, to see what's being typed.
- A value is sent only once something is typed, and an emptied input goes back to the stored state, so the field never sends `''`. **Keep current** cancels a replace or a remove.

It takes the props the other fields take (`label`, `field` or `:model`, `disabled`, `optional`, `placeholder`), plus `required`.

::callout{icon="i-heroicons-shield-check"}
The field never shows a stored value because it never receives one. Your API must still leave secrets out of every response, including the item's `GET`, its collection and its real-time updates.
::

## Read-Only Details and Tables

Two kit components show data an admin reads but doesn't edit:

`<CwaUiDetailList>` shows labelled values, in two columns where there's room. `items` is a list of `{ label, value }`; an empty value shows a dash, read as "Not set". The `value` slot, given `item` and `index`, formats a value.

`<CwaUiDataTable>` shows rows of data. `columns` is a list of `{ key, label, align? }`, `rows` a list of objects read by each column's `key`, and `label` names the table for screen readers. `empty` is what it says with no rows (default "None"). A wide table scrolls sideways inside the dialog. The `cell` slot, given `row`, `column` and `value`, formats a cell:

```vue
<CwaUiDataTable label="Order lines" :columns="lineColumns" :rows="lines">
  <template #cell="{ column, value }">
    {{ column.key === 'total' ? formatMoney(value) : value }}
  </template>
</CwaUiDataTable>
```

`<CwaAdminResourceId :iri>` shows a resource's ID with a **Copy ID** button, as on the built-in Info tabs.

The other kit components (`<CwaUiDialog>`, `<CwaUiFormSection>`, `<CwaUiButton>`, `<CwaUiBadge>` and the fields) are listed in [The CWA Layer › Reusable UI Components](/nuxt-module/cwa-layer/overview#reusable-ui-components).
