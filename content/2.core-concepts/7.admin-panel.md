Content is edited **on the live page**: the admin bar overlays the front end, and the manager panel slides up from the bottom when you click a component. A few admin pages under `/_cwa` manage records that aren't on a page, such as layouts, routes and users.

This page is a tour for editors and developers new to CWA.

## Access

Log in at `/login` as a content admin: a user with `ROLE_CMS_ADMIN`, or `ROLE_ADMIN`, which includes it. Once logged in, the admin bar appears at the top of every page.

## The Admin Bar

The bar shows:
- **Edit** / **Done** toggle — activates inline editing mode
- A menu linking to the admin pages: Layouts, Pages, Data (shown once the API has a page data class), Routes, Users and Site settings, plus Extensions when the site has an extension with admin pages
- The current page's name with a cog — click it to open that page's settings
- A loading indicator for API activity
- A warning icon with a count beside **Edit** / **Done** when the page has component groups that your code no longer shows (see [Stranded Component Groups](#stranded-component-groups))

![The admin bar across the top of a live page: the Edit button, the current page's name with its settings cog, and the admin menu open on Layouts, Pages, Data, Routes and Users, with Site settings, My account, Sign out and About the CWA beside them](/images/docs/admin-bar-menu.webp)

## Edit Mode

When edit mode is active:
- An **empty** component group shows a plain box with a **+** hotspot. Hover or focus the **+** to see why the group is empty, and click it to open the "Add a component" dialog. Outside edit mode, an admin sees what a visitor sees: nothing at all for an empty group
- **Click any component** to select it and open the manager panel. A faint outline shows which component a click would select
- The manager panel slides up from the bottom and shows your component's admin tabs
- **Right-click** a component in the live page layout (not in the `/_cwa/` admin pages) to open a menu of nested boxes, one for each resource under the cursor. Use it to select the parent component position or group instead of the innermost component. On a phone, a long press opens it
- Every component is also a keyboard tab stop: **Enter** or **Space** selects it, and **Shift+F10** opens the same menu
- **Click a link** to open a menu at the click point. **Edit** (with the component's name) selects the component the link is in, as any other click does. The second item follows the link: **Visit** with the link's path for a page on this site, **Open in new tab ↗** for another site, or **Go to section** for a link within the page. **Visit** saves any field still waiting to be saved before it leaves. A link in the layout while you're editing the page (or the other way round) asks **Edit the shared layout?** or **Edit the page?** first
- Other ways of leaving the page, such as a `<NuxtLink>` your code follows, are blocked so an edit in progress isn't lost. The browser's back and forward buttons still work. See [Navigation Guard](/nuxt-module/cwa-api/admin#navigation-guard)

## Adding a Component

1. Enter edit mode
2. In an empty group, click its **+** hotspot. In a group that already has content, click a component to select it, then open **More actions** (the ⋮ beside the manager panel's publish button) and choose **Add before** or **Add after**. With the group itself selected, its **Group** tab and the same menu have **Add to start** and **Add to end**. In a full group these are greyed out, with the reason; see [`<CwaComponentGroup />` › Limiting the Number of Components](/nuxt-module/cwa-components/cwa-component-group#limiting-the-number-of-components)
3. The "Add a component" dialog lists the component types, each with the name, icon and group its `defineCwaConfig` gives it. Choose one to see its description and, if it has them, a choice of UI and style
4. Click **Add**. The new component appears in the group with the manager panel open, still unsaved: fill in its tabs, then click **+ Draft** (or **+ Add** for a component that isn't publishable). Its menu also has **Add and publish** and **Discard**. A component whose `defineCwaConfig` has `instantAdd: true` shows **Add now** instead and is saved straight away
5. A file chosen before you save, such as an image, is uploaded as soon as the component is saved

## Reordering

Select a component and open the manager panel's **Order** tab. Its **Position** field says where the component is in the group, from the top: use **Move up** / **Move down** or type a number.

To drag instead, select the group itself (right-click the component and choose the group) and turn on **Enable reordering** in its **Group** tab. Then drag any component in the group, with a mouse or a finger: the whole component is the handle, with a small grip in its corner. A line shows where it will land, and nothing on the page moves until you drop it. A click still selects the component.

The module sends the group's new order to the API in one request, and the API chooses each position's `sortValue`. Moves made while a request is running are sent together in the next one. When the response comes back, the module updates the group from it, so a component another editor added in the meantime appears in its place.

## Cloning a Component

A clone puts the **same component** in another place. It isn't a copy: both places show one component with one IRI, so an edit or a publish in either place changes it everywhere. Use it for something that should stay identical in several places, such as a call to action shown on several pages. To take a component out of one place and put it in another, use Move instead (see [Moving a Component](#moving-a-component)).

1. In edit mode, select the component. Beside the manager panel's publish button, open **More actions** (the ⋮ button, whose menu also has **Add before** / **Add after**) and choose **Clone**. It's offered for any saved component, even when its own group is full.
2. Clone mode starts. A bar in the admin bar reads **Cloning: *name* — “*text*”**, where the text is the start of the component's content, then *Click where it should go* and a **Cancel** button. The instance you started from gets a thick yellow outline, and every other instance of the component on screen a thin one.
3. Click where it should go. The spot gets a blue outline, and a menu opens at the click point with the options adding a component offers there (see [The placement menu](#the-placement-menu) below).
4. Choose an option. If the spot is in the layout while you were editing the page, or the other way round, you're asked **Edit the shared layout?** (*It will appear on every page that uses this layout.*) with **Edit layout** and **Cancel**, or **Edit the page?** (*It will appear on this page only, not on other pages using the layout.*) with **Edit page** and **Cancel**.
5. Clone mode ends, and the new instance flashes and is selected.

In clone mode, a click never selects a component: it opens the placement menu. To place the component on another page, click a link to it. The menu then starts with **Visit** and the link's path; choose it, and you can place the component on the page it opens straight away. A route that redirects takes you to its target. Clone mode stays on across navigation.

Clone mode ends when you click **Cancel**, press **Escape**, click **Done**, sign out, or place the component. **Escape** or a click outside an open menu closes only the menu, and clone mode stays on. A right-click opens the browser's own menu.

When the selected component is the draft of a published component, the clone places the published component, which the draft belongs to.

### The placement menu

The menu is headed after the component you clicked next to: **Clone next to “*text*”**, from the start of that component's content, or its name when it has no text. When you clicked a group rather than a component, it's titled **Clone Here**.

The options depend on what you clicked:

| You clicked | Options |
|-------------|---------|
| A component in a group | **Add before**, **Add after** |
| A group that has components | **Add to Start**, **Add to End** |
| An empty group | **Add here** |
| A component position bound to a page data property, on a page data page (see [Your First Dynamic Page](/guides/your-first-dynamic-page)) | **Use here**, which sets the page data's property to the component. It's offered beside the group options when the click also reached a group |
| A link | **Visit** and the link's path first, then the options for where you clicked |

An option that isn't allowed is greyed out, with an ⓘ beside it: click it to see why. When no option is allowed, the menu has one greyed-out row, **Nothing can be placed here**, whose ⓘ lists every reason. The reasons are:

- **This group is full**: the group has reached its maximum, see [`<CwaComponentGroup />` › Limiting the Number of Components](/nuxt-module/cwa-components/cwa-component-group#limiting-the-number-of-components).
- **This group does not allow *Type***: the group's allowed components don't include it, see [`<CwaComponentGroup />` › Allowed Components](/nuxt-module/cwa-components/cwa-component-group#allowed-components).
- **This group does not allow its UI** or **This group does not allow its style**: the group limits the UIs or styles the component may use, and the component's aren't among them, see [`<CwaComponentGroup />` › Limiting UIs and Styles](/nuxt-module/cwa-components/cwa-component-group#limiting-uis-and-styles).
- **This component type is not known**: the API's documentation doesn't list the component's type.
- **This field takes *Type*, not *Type***: the page data property holds a different component type.
- **This is inside the component being cloned**: see the callout below.

Component types are named by their display name.

When no reason applies but nothing can be placed, the ⓘ says **A component cannot be added here**.

Under the heading, one muted line says where the component will show. On a phone, the menu opens as a sheet from the bottom of the screen. A spot in the layout, while you're editing the layout, says **Shared layout: this appears on every page**. A spot in the other scope says **This is in the layout: it will appear on every page using it**, or **This is in the page: it will not appear on other pages using the layout**. When the page data property already holds another component, the line also says **This replaces *Type***.

If the API refuses the clone (a `422`), the error is shown and clone mode stays on, so you can pick another target. If the component has been deleted in the meantime, the error reads **The component being cloned no longer exists** and clone mode ends. The same happens when the API answers `400` *Item not found*, as it does for a deleted component.

::callout{icon="i-heroicons-exclamation-triangle" color="warning"}
**A component can't be placed inside itself.** A component that holds its own component groups, such as a two-column block, can't be cloned into one of its own groups at any depth. The menu greys these targets out, and the API also refuses them with a `422` on `component` (see [Component Groups & Positions › A Component Can't Contain Itself](/api/components/component-groups#a-component-cant-contain-itself)).
::

## Moving a Component

Move takes the instance you selected out of its place and puts it somewhere else. The component itself doesn't change, and any other place that shows it keeps showing it. Clone adds a place; Move changes one.

::callout{icon="i-heroicons-exclamation-triangle" color="warning"}
**Move needs api-components-bundle `2.0.0-alpha.32` or later.** A move is one `POST {component}/move` request, which the API applies in one transaction, see [Component Groups & Positions › Moving a Component](/api/components/component-groups#moving-a-component). Update the module and the bundle together: see [Module Setup › Bundle versions](/nuxt-module/module-setup#bundle-versions).
::

Moving works like cloning, with the same mode, bar and placement menu:

1. Select the component, open **More actions** and choose **Move**. It's offered for a saved component in a component position, and for a component that a page data property holds.
2. The bar reads **Moving: *name* — “*text*”**.
3. Click where it should go. The menu is headed **Move next to “*text*”** or **Move Here**, with the same options as for a clone.
4. Choose an option. The component leaves its old place, appears in the new one, flashes and is selected.

A move can go into an empty page data property, out of one into a group, and into the same property on another page data page: click a link to that page and choose **Visit** to get there. The menu differs from a clone's in these ways:

- **This is where it already is**: the option would leave the component where it is, such as **Add before** or **Add after** on the instance you're moving, or **Use here** on the property that holds it.
- **This field already holds *Type*: a move cannot replace it**: **Use here** is disabled on a page data property that holds another component. Clear it first, or clone instead.
- A full group isn't a reason when the component is moving within that group.
- Moving a component out of the layout into a page says **This takes it out of the layout: it will no longer appear on other pages**.

If the component has been deleted in the meantime, the error reads **The component being moved no longer exists** and move mode ends.

## Shared Components

A component in more than one place is shared. Selecting it outlines every instance on screen: the one you clicked as usual, and each other one with a faint thin outline. Editing in one place updates them all.

Beside the manager panel's publish button, a badge reads **Shared · *N* places** (only the number on a phone). Click it for the list of places, titled **Used in *N* places**:

- **Layout: *reference*** *on every page using it*, for a component in a layout's group.
- Each page it shows on, by title or path, and linked when it has a route. The page on screen is marked **This page**. A page that shows it as the default for a page data property is under **Template default for *property***.
- **and *N* more** when a place shows on more pages than the list has room for, and **and *N* more places** when there are more places than it lists.

The links work while you're editing.

The manager panel's Info tab says **Used in *N* locations** too, see [Deleting a component](#deleting-a-component).

::callout{icon="i-heroicons-information-circle"}
**The list of places needs api-components-bundle `2.0.0-alpha.32` or later**, which lists them in `GET {component}/usage` (see [Component Groups & Positions › Where a Component Is Used](/api/components/component-groups#where-a-component-is-used)).
::

## The Manager Panel

When you click a component, the manager panel slides up from the bottom of the page. Its tabs come from two places:

- **Your tabs:** one for each file in the component type's `admin/` folder. Each file calls `useCwaResourceManagerTab({ name: 'Tab Name' })` and renders one `<CwaUiManagerTab>` holding the module's admin fields, such as `CwaUiInput`, `CwaUiSelect`, `CwaUiToggle`, `CwaUiFileUpload` and `CwaUiLinkInput`. See [Components › The Admin Tab](/core-concepts/components#the-admin-tab).
- **The module's tabs:** **UI** (the component's UI variant and style, shown when it has any), **Order**, **Publish** and **Info**.

A tab is one row of fields. A field saves on its own a moment after you stop typing, and shows its state as it does. If the save fails, the field says **Not saved** and offers **Retry** and **Reset**. If you've already selected another component or left the page, a message names the component and offers **Show me**, **Retry** and **Reset**. Text longer than a line isn't edited in a tab: you edit it on the page, where it sits. In edit mode, a component can let you click a heading and type, and rich text has its own editor in place. A tab can offer a button that takes you there.

Changes in the admin tabs apply to the **draft** version of the component. Click **Publish now** in the panel to make changes live.

The panel's status word says what you have selected: **Draft**, **Scheduled** or **Live**. Click it for an explanation, such as who can see a draft.

### Scheduling a Publish

A component with a draft can be published now or at a later time. Select it and open the manager panel's **Publish** tab. For a draft it has a **Schedule** toggle, and the panel's main button follows it:

- **Schedule off:** the button reads **Publish now** (**Publish** on a phone). Click it to publish the draft straight away.
- **Schedule on:** pick a date and time in **Go live**, then click the button, which now reads **Schedule**. The status changes to **Scheduled**. Type into the day, month, year, hour and minute, or use the calendar button. Minutes go in steps of 5, and times before you opened the tab can't be chosen.

A scheduled draft opens with the toggle on. To keep it unpublished, open **More actions** (the ⋮ beside the button) and choose **Cancel schedule**, which clears the date.

When the component also has a live version, the tab has an **Edit published version** toggle: turn it on to select the live version, whose changes go live immediately. A live component with no draft says *Live. There is no draft to publish.*

Publishing straight away uses the API server's clock, not your computer's. **Publish**, **Publish now**, a **Schedule** whose time has already passed, and adding a component that is published straight away all send `"publishedAt": "now"`, and the API sets the time when it saves. So a publish works even when your computer's clock is ahead of the server's. A future schedule sends the date and time you picked.

![The Publish tab for a scheduled draft: Scheduled, the Schedule toggle switched on, the date picker set to 28/11/2026 10:30, and the Schedule and Cancel schedule buttons](/images/docs/admin-publish-scheduled.webp)

Times are in your computer's time zone and are saved as UTC. Hover the calendar button to see the zone and its offset at the chosen date, such as "Times are in Europe/London, UTC+01:00", so a clock change between now and then is visible. Nothing is pushed to open browsers at that moment, so a page that is already open shows the change the next time it loads.

### Deleting a component

Deleting is on the panel's **Info** tab, which also shows the component's ID with a **Copy ID** button. The delete button reads **Delete**, or **Discard** while a new component is still being added.

A component used in more than one place (see [Shared Components](#shared-components)) shows **Used in *N* locations** on the Info tab. The count includes component positions and page data fields that hold it.

When the component is a draft, or is used in more than one place, **Delete** asks **Delete this component?** and offers only the choices that apply:

- **Remove from here**, for a component used in more than one place, keeps the component and removes it from the place you selected it in: it deletes that component position, or for a component position bound to a page data property it clears that property. It's offered only when you selected the component inside a component position.
- **Delete draft**, for a draft of a live component, discards the unpublished changes. The live version stays.
- **Delete entire component**, for a draft of a live component, deletes the draft and then the live version, everywhere it is used.
- **Delete draft**, for a draft that has never been published, deletes the component, as there is no live version to keep.
- **Delete from all *N* places**, for a live component used in more than one place, deletes it everywhere.
- **Cancel**, on its own side of the row. It has the focus, unless **Remove from here** is offered, which has it then. Pressing **Escape** or closing the dialog counts as Cancel.

A live component in one place, or anything that isn't publishable, such as a component group or position, asks **Delete this resource?** with **Delete** and **Don't delete**.

## Managing Routes

A page's or page data's route is on the **Routes** tab of its settings. The settings open from the admin lists, from the cog beside the page's name in the admin bar, and from `/_cwa/routes`, which lists every route: opening one shows the settings of the page it leads to. The settings open as a panel that slides in from the right.

The tab shows the route's **Path** with a **Copy path** button and a status: **Live**, **Scheduled**, **Not live**, or **Inherited scheduled** / **Inherited not live** when a parent route holds the page back. **Edit route** opens the route editor. Below it, **Redirect to**, **Redirected from** and **Child routes** each open their own view, with their own save button. A page with no route offers **Add a route** instead.

### Editing a path

The route editor's **Path** has two parts when the route has a required start: the path of the nearest parent with a route, then the page data type's route prefix if it has one (see [Routes › The Required Start of a Path](/api/routes#the-required-start-of-a-path)). The start is shown locked in front of the field, such as `/blog/`, and you type only the rest, in a field labelled **Rest of the path after /blog/**. This is the same for a new route and an existing one. With no routed parent and no prefix, it's one **Path** field and you type the whole path. Spaces become hyphens as you type, and a `?` or `#` is refused. A path the API refuses shows its message under the field.

When the path isn't the one CWA would suggest, a box below it reads **Recommended:** with the required start and the slug of the page title, and says which title it's based on. Click **Use this** to fill it in.

![The route path editor for Chapter Two: a Prefix select set to /topic-1 beside the Route suffix /chapter-two, Save Route, the Visibility select, and the SEO recommendation below saying the recommended route is in use](/images/docs/admin-route-path-editor.webp)

::callout{icon="i-heroicons-photo"}

When you change a path, the editor says *The old path, /old, keeps working: it will redirect here.* If child routes start with the old path, a checkbox reads **Also change the *N* child routes that start with /old/**. Ticked, it renames them to keep them under the new path, each with a redirect from its old path. Left unticked, only this route is renamed (with a redirect from its old path); the children keep their old paths. Click **Save route** (or **Add route** for a new one).

A new page or page data gets its route before it's created: its **Routes** tab offers the path, with the recommendation, and when it goes live, and the route is created with the page. Leave the path empty to create it without a route.

::callout{icon="i-heroicons-information-circle"}
A child page can't get a route while its parent page has none. Its Routes tab says *The parent page has no route yet.* with a button to open the parent: add a route there first.
::

### Moving a page

Changing a page's **Parent page**, or a page data's **Parent data**, moves its route under the new parent when you save, and its child pages' routes with it: `/blog/my-post` becomes `/news/my-post`. Each old path redirects to the new one. If a new path is already taken, the parent field shows why, and nothing moves (see [Routes › Moving a Page](/api/routes#moving-a-page)).

When the page you're looking at moved, itself or as a child of the moved page, the address bar changes to its new path. The change doesn't add a step to the browser's history.

### Visibility

The route editor's **Go live** setting decides whether the public can see the page:

- **Live** — public now
- **Scheduled** — public from the date and time you pick in the **Goes live** field. Times are in your computer's time zone: hover the calendar button to see the zone and its offset at that date, for example "Times are in Europe/London, UTC+01:00"
- **Not live** — hidden, with the path still reserved. Use it to take a page offline without deleting its route

A line under it says what saving will do, such as *The route goes live as soon as you save.* The change is saved with **Save route**.

Choosing **Live** on a route that is already live keeps its go-live date, shown as *Live since …*. Only a route that was scheduled or not live gets the current time.

Visibility is inherited: a page can't go live before its parent route does, so if the parent is scheduled or not live, the Routes tab says what is holding the page back. The routes list and each route's status show the state that actually applies, with the go-live date for scheduled routes.

As an editor you can still open, preview and edit a scheduled or hidden page. Visitors get a 404, and it stays out of the sitemap until it goes live. For the full rules see [Scheduling and Taking Routes Offline](/api/routes#scheduling-and-taking-routes-offline).

A page or page data with no route is private, unless you turn on **Public without a route**. The toggle is on the **Routes** tab, shown only while the page has no route, and it's saved with the page's settings. ### Redirects

Two rows on the Routes tab manage redirects:

**Redirect to** — the outbound `redirect` field. Its view says *Not redirecting* until you click **Redirect to another page**, choose a page in **Send visitors to** and click **Redirect**. Once set, it shows the redirect with **Change** and **Remove**. While edit mode is on, the admin doesn't follow the redirect, so the page stays editable; choosing **Visit** on a link to it does follow it.

**Redirected from** — the `redirectedFrom` list. Shows all other routes that forward visitors to this route, and lets you add an old address with **Add**. Useful for auditing redirect chains and identifying stale paths.

Redirects can be chained. The API walks the chain when it serialises a route and returns the final destination as `redirectPath` — the Nuxt module's route middleware then issues a `308` to it. A chain that loops back on itself is rejected with a circular reference error rather than being followed.

To seed redirects in fixtures, see [Builder Reference › Seeding Redirects](/api/data-fixtures/builder-reference#seeding-redirects).

## Editing Together

Two admins can edit the same page at the same time. Each one's saves appear on the other's screen as soon as the API has them, in the page and in the manager panel, with no reload.

You can see each other as you work. The admin bar shows an avatar for each other admin on the page, in their colour, and how many are on other pages; click the avatars to see where each one is and what they're doing. In edit mode, a component another admin has selected is outlined in their colour with their name, and so is a field they're typing in.

::callout{icon="i-heroicons-photo"}
IMAGE: The admin bar with two coloured avatars and "+1 elsewhere", above a page where one component is outlined in teal with the flag "Ana Ruiz is editing"
::

If the other admin saves a field you've changed but not saved, your value stays and the control shows ***Ana Ruiz* changed this · Use theirs / Keep mine**. **Use theirs** drops your change; **Keep mine** saves yours over theirs. Publishing chooses **Keep mine** for you.

If the other admin deletes the component you have selected, it's deselected. If they publish the draft you're editing, your unsaved changes are saved to a new draft.

Co-editing needs api-components-bundle `2.0.0-alpha.36` or later. The details, what it needs from the API's CORS config and how to turn it off are in [Real-Time Updates › Co-Editing in the Admin](/nuxt-module/component-helpers/real-time-updates#co-editing-in-the-admin).

## The Admin Pages (`/_cwa/`)

The admin bar's menu opens the admin pages under `/_cwa`: Layouts, Pages, Data (your page data records, such as blog articles, shown once the API has a page data class), Routes, Users and Site settings, and Extensions for an extension's own admin area. They're separate screens for managing records, while content is still edited on the page itself. [Admin Panel Reference › Admin Routes](/nuxt-module/cwa-layer/admin-panel#admin-routes) lists every route.

Each list has a search field, a sort select and a create button named after what it creates, such as **Layout** or **Page**; the pages list can also be filtered to **Static** or **Dynamic** pages. A row opens that record's settings in a panel that slides in from the right, with tabs such as **Details** and **Info**, and **Routes** for pages and page data. Nothing saves until you click the panel's save button, which counts your changes; when you're creating a record it reads **+** and the record's name, such as **+ Page**. The Info tab shows the record's ID with a **Copy ID** button. On a phone, selects and menus open as sheets from the bottom of the screen.

Site settings has **General**, **SEO**, **Maintenance** and **About** tabs, with one **Save** across them. The address follows the tab (`/_cwa/settings#seo`), so reloading or going back returns to the tab you were on.

## Maintenance

Two admin tools clean up what content and code changes leave behind. Both are covered in full in [Maintenance](/nuxt-module/cwa-layer/maintenance).

### Stranded Component Groups

If you rename a group's `reference` in code, the old group stays attached to the page with its content, and visitors stop seeing it. The admin bar then shows a warning icon with a count beside **Edit** / **Done**. Click it to merge each stranded group into one the page shows, or delete it. See [Stranded Component Groups](/nuxt-module/cwa-layer/maintenance#stranded-component-groups) for what the check finds and the cases that switch it off.

### Orphaned Resources

Removing content can leave records nothing uses: a component nothing displays, an empty position, a group nothing owns, or an uploaded file. The **Maintenance** tab of site settings (`/_cwa/settings`) can scan for them, and `/_cwa/orphaned` lists them so you can review and delete them. See [Orphaned Resources](/nuxt-module/cwa-layer/maintenance#orphaned-resources) and [Orphaned files](/nuxt-module/cwa-layer/maintenance#orphaned-files).
