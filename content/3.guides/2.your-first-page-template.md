---
title: Your First Page Template
description: Create a page template that places a page's component groups inside a layout, using CwaComponentGroup.
---

Your `landing` layout is in place — but its `<slot />` is empty. A page template fills it. It's a Vue file that places the page's component groups: where the main content goes, where the sidebar lives.

Each `CwaComponentGroup` in it declares a component group. You declare which groups exist and what they're called; editors fill them with components at runtime. The template's `PrimaryPageTemplate.vue` has a single group; this guide builds a two-column one beside it.

![The two-column page template in edit mode, with the main component group holding a Quote and the aside component group outlined with its + hotspot](/images/docs/guide-landing-edit.webp)

## The File

Create `app/app/cwa/pages/TwoColumnPageTemplate.vue`:

```vue
<template>
  <div class="mx-auto grid max-w-7xl gap-10 px-4 py-10 md:grid-cols-3">
    <div class="md:col-span-2">
      <CwaComponentGroup
        reference="main"
        :location="props.iri"
      />
    </div>
    <aside>
      <CwaComponentGroup
        reference="aside"
        :location="props.iri"
      />
    </aside>
  </div>
</template>

<script setup lang="ts">
import type { IriProp } from '#cwa/composables/cwa-resource'

const props = defineProps<IriProp>()
</script>
```

### Key points

**`defineProps<IriProp>()`** — every page template receives its page's IRI as a prop. The module passes this automatically when rendering the page.

**`CwaComponentGroup reference="main" :location="props.iri"`** — declares a component group called `main` owned by this page. Any components the editor adds here are stored against this specific page record. Each `CwaComponentGroup` with a unique `reference` is a separate, independently managed group, so `aside` is a second one.

::callout{icon="i-heroicons-information-circle"}
The `location` must be the IRI of a **layout, page, or component**. For a page's groups, always use `props.iri` — the IRI the module passes in automatically for the current page.
::

## Register in nuxt.config

Add an entry next to the template's `PrimaryPageTemplate`:

```ts
// app/nuxt.config.ts
cwa: {
  pages: {
    PrimaryPageTemplate: {
      // the template's existing entry
    },
    TwoColumnPageTemplate: { // [!code focus]
      name: 'Two Column Page', // [!code focus]
    }, // [!code focus]
  }
}
```

The key is the filename. Add `classes` as you did for the layout if this template needs style options; it works the same way.

## Create a Page Record

A page template Vue file defines the structure; a Page record in the database gives it a URL and assigns it to a layout.

**Naming convention:** the page template's global component name is the filename prefixed with `CwaPage` — `TwoColumnPageTemplate.vue` → `CwaPageTwoColumnPageTemplate`. That full name is what the page's `uiComponent` stores, whether you create the page in the admin or from fixtures.

### Via the admin

Go to `/_cwa/pages` → the **+** button → choose **Two Column Page** as the **Page UI** (stored as `uiComponent: CwaPageTwoColumnPageTemplate`), choose the `landing` layout, and click **Add Now**. The page opens on its **Routes** tab: create a route with the path `/landing`.

### Via fixtures

Add the page to `build()` in `api/src/DataFixtures/Parts/LandingScaffoldPart.php`, after the layout:

```php
public function build(CwaFixtureBuilder $cwa, ScaffoldState $state): void
{
    $cwa->layout('landing', 'Landing');

    $cwa->page('landing-page', 'TwoColumnPageTemplate', layout: 'landing', route: '/landing') // [!code focus]
        ->title('Landing'); // [!code focus]
}
```

`layout: 'landing'` refers to the layout's reference from `$cwa->layout('landing', …)`, not its `uiComponent`. The route is `/landing`, because the template's own home page already has `/`. Load it again from the project root:

```bash
docker compose exec php bin/console doctrine:fixtures:load --append
```

The layout already exists, so it's kept; the page and its route are created. See [Data Fixtures](/api/data-fixtures/getting-started) for the full API.

Visit `https://localhost/landing`: the landing layout's banner and footer wrap your empty two-column page. Sign in and click **Edit** to see a **+** in each group.

::callout{icon="i-heroicons-information-circle"}
This page has one URL. For repeating content, such as blog articles, many URLs share one **template page** instead. [Your First Dynamic Page](/guides/your-first-dynamic-page) builds one, using this page template.
::
