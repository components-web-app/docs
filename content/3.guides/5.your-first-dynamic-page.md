title: Your First Dynamic Page
description: Build news articles that share one template page, each with its own URL and its own Quote, using a page data entity and a dynamic component position.
---

Every page so far has its own URL and its own content. Repeating content, such as blog articles, events or products, works differently. Each item is a **page data** record with its own URL and fields, and they all share one **template page** for their structure.

This guide builds news articles. Each article has its own Quote, shown in the `main` region of the `TwoColumnPageTemplate` you built in [Your First Page Template](/guides/your-first-page-template). If you picked the blog feature, the template's `BlogArticleData` and `BlogScaffoldPart` are a complete working example of the same pattern.

::callout{icon="i-heroicons-exclamation-triangle" color="warning"}
**"Page template" and "template page" are different things.** A *page template* is a Vue file, such as `TwoColumnPageTemplate.vue`; the admin calls it the **Page UI**. A *template page* is a page record with `isTemplate: true` that many page data records share; the admin calls it a **Dynamic** page. This guide makes a template page that renders through the page template you already have.
::

## The File

The Vue file already exists: articles render through `TwoColumnPageTemplate.vue`. The new file is the PHP entity for the articles' data.

Create `api/src/Entity/NewsArticleData.php`:

```php
<?php

declare(strict_types=1);

namespace App\Entity;

use ApiPlatform\Metadata\ApiResource;
use App\Entity\Component\Quote;
use Doctrine\ORM\Mapping as ORM;
use Silverback\ApiComponentsBundle\Entity\Core\AbstractPageData;

#[ApiResource(mercure: true)]
#[ORM\Entity]
class NewsArticleData extends AbstractPageData
{
    #[ORM\ManyToOne(targetEntity: Quote::class)] // [!code focus]
    #[ORM\JoinColumn(nullable: true, onDelete: 'SET NULL')] // [!code focus]
    public ?Quote $quote = null; // [!code focus]
}
```

`AbstractPageData` gives each article a `title` and `metaDescription`, which the module uses for the page's `<title>` and meta description. The `quote` field holds the component each article shows. A field like this must be typed as a component class.

Generate and run the migration from the project root:

```bash
docker compose exec php bin/console doctrine:migrations:diff
docker compose exec php bin/console doctrine:migrations:migrate
```

As in the last guide, review the migration in `api/migrations/` and delete its `down()`: the template's migrations are [upward-only](/api/bundle-setup#database-setup).

## Register in nuxt.config

Add a `pageData` entry, keyed by the class's short name:

```ts
// app/nuxt.config.ts
cwa: {
  pageData: {
    NewsArticleData: { // [!code focus]
      name: 'News Articles', // [!code focus]
      properties: { // [!code focus]
        quote: 'Article Quote', // [!code focus]
      }, // [!code focus]
    }, // [!code focus]
  }
}
```

`name` is how the admin lists the type at `/_cwa/data` and in its selects. `properties` gives each component field a label. Both are optional: without them the admin shows `NewsArticleData` and a label made from the field name.

## Create in the API

Three records make a dynamic page work:

1. a **template page**, with a region bound to the `quote` field;
2. a **page data** record for each article, naming the template page;
3. a **route** for each article.

The region binding is a **dynamic component position**. Instead of holding one component, it shows whatever component the current article holds in its `quote` field.

### Via the admin

**The template page.** Go to `/_cwa/pages` → **+**. Switch the type select at the top from **Static** to **Dynamic**, give it the reference `news-template`, choose **Two Column Page** as the **Page UI** and the `landing` layout, and click **Add Now**. A template page has no route.

**The dynamic position.** Open the template page with the eye icon in its settings, and click **Edit**. Click **+** in the main region. The Add Component dialog has a **Dynamic** option as well as the component types: choose it, then **News Articles** as the **Data type** and **Article Quote** as the **Field**, and confirm.

::callout{icon="i-heroicons-photo"}
IMAGE: The Add Component dialog on the template page, with Dynamic selected, News Articles as the Data type and Article Quote as the Field
::

**An article.** Go to `/_cwa/data` → **News Articles** → **+**. Give the article a title, choose `news-template` as its **Dynamic Page**, and click **Add Now**. It opens on its **Routes** tab: create a route with the path `news/first-article`.

**Its quote.** Visit `https://localhost/news/first-article` and click **Edit**. Select the main region's dynamic position. Its **Data Placeholder** tab has an **Add Quote** button: click it, type the quote, and click **Publish**. The quote belongs to this article; the next article you create gets its own.

In the admin lists, **blue** records are static pages, **yellow** are template pages, and **green** are page data records, shown **orange** until they have a route. So you can see at a glance what is shared structure and what is one item of content.
::

### Via fixtures

Add to `build()` in `api/src/DataFixtures/Parts/LandingScaffoldPart.php`:

```php
use App\Entity\Component\Quote; // [!code focus]
use App\Entity\NewsArticleData; // [!code focus]

// ...

public function build(CwaFixtureBuilder $cwa, ScaffoldState $state): void
{
    // ... the landing layout and page from the earlier guides

    $cwa->page('news-template', 'TwoColumnPageTemplate', layout: 'landing', isTemplate: true) // [!code focus]
        ->group('main')->pageDataPosition(NewsArticleData::class, 'quote'); // [!code focus]

    $quote = new Quote(); // [!code focus]
    $quote->text = 'News is what somebody does not want you to print.'; // [!code focus]
    $quote->setPublishedAt(new \DateTime()); // [!code focus]
    $cwa->persist($quote); // [!code focus]

    $article = new NewsArticleData(); // [!code focus]
    $article->setTitle('First article') // [!code focus]
        ->setMetaDescription('The first news article.'); // [!code focus]
    $article->quote = $quote; // [!code focus]

    $cwa->pageData($article, template: 'news-template', route: '/news/first-article'); // [!code focus]
}
```

`isTemplate: true` makes the page a template page, so it gets no route. `pageDataPosition()` takes the page data class and the field name, and creates the dynamic position in the `main` group. `pageData()` takes the template page's reference, not its `uiComponent`.

Load it from the project root:

```bash
docker compose exec php bin/console doctrine:fixtures:load --append
```

::callout{icon="i-heroicons-exclamation-triangle" color="warning"}
`--append` keeps anything that already exists. An article whose route path already exists is kept as it is, and so is its quote, so a second load doesn't create another one. A group that already exists is kept too, without new positions, as in [Your First Component](/guides/your-first-component#via-fixtures). See [Appending to an Existing Site](/api/data-fixtures/appending#appending-to-an-existing-site).
::

Visit `https://localhost/news/first-article`: the landing layout wraps the two-column page, and the main region shows this article's quote.
