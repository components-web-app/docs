## Prerequisites

- [Docker Desktop](https://www.docker.com/products/docker-desktop/) (or Docker Engine + Compose)
- Node 22.13 or later and pnpm 12 (for running the CLI and the Nuxt app locally)

::callout{icon="i-heroicons-information-circle"}
The template moved to pnpm 12 in `2.0.0-alpha.4` ([`e919d06`](https://github.com/components-web-app/components-web-app/commit/e919d069d24b7e74f59395d49772b394a70b036d)). If you move an older project to pnpm 12, remove `confirmModulesPurge` from `pnpm-workspace.yaml` too: pnpm 12 refuses settings it doesn't know, so every install fails with `ERR_PNPM_UNRECOGNIZED_WORKSPACE_SETTINGS`.
::

PHP, Composer, and all API dependencies run inside Docker — nothing else to install. The Nuxt app's own requirements, including Pinia 4, come in through `pnpm install`. If you're upgrading an existing app, check the [module requirements](/nuxt-module/module-setup#requirements) — the module now needs `@pinia/nuxt` `^1.0.2`, and Nuxt won't boot on an older copy.

## 1. Scaffold your project

Run the interactive CLI:

```bash
pnpm create cwa my-project
```

The CLI will ask four questions:

| Prompt | Options |
|--------|---------|
| **Project name** | The directory to create |
| **CI/CD pipeline** | GitHub Actions, GitLab CI, or none |
| **Features** | Navigation links, HTML content editor, image uploads, blog, nested pages, forms (multiselect) |
| **Include fixtures?** | Scaffolds sample content so the site works out of the box |

After answering, the CLI downloads the template, strips the code for features you didn't pick, and generates a `README.md` tailored to your choices. It then asks two more questions:

- **Start the Docker stack now?** Accept. It runs `docker compose up -d` in the new project.
- **Also install `app/` dependencies on this machine?** Optional, and off by default. The `app` container installs the Nuxt dependencies itself, so only say yes if your editor needs them for type support.

::callout{icon="i-heroicons-information-circle"}
`create-cwa` has the same version as the template release it installs. `create-cwa` `2.0.0-alpha.1` downloads the template, and its `cwa-manifest.json` of feature options, from the template's `v2.0.0-alpha.1` tag, so the same CLI version always installs the same template. Template changes reach new projects only in a new release.
::

::callout{icon="i-heroicons-beaker"}
To install from a different branch or tag, for example to try unreleased changes, pass `--ref`:

```bash
pnpm create cwa my-project -- --ref main
```

`create-cwa` `0.x` versions always installed the template's `main` branch.
::

## 2. Load the sample content

If you answered yes to **Include fixtures?**, load them once the `php` container is healthy. Run this from the project root:

```bash
docker compose exec php bin/console doctrine:fixtures:load --append
```

This creates an admin account (`admin` / `admin`) and seeds a layout, a home page at `/` with a `Title` component, and sample content for each feature you picked. With `--append` it is safe to run again: it keeps what is already in the database and only creates what is missing. It does reset the admin's password to `admin` each time.

::callout{icon="i-heroicons-information-circle"}
**Without fixtures**, the database starts empty: no layout, no pages and no users. Create an admin account instead, and answer the prompts for username, email and password:

```bash
docker compose exec php bin/console silverback:api-components:user:create --admin
```

The `--admin` flag gives the account `ROLE_ADMIN`; without it you can't open the admin panel. Until a page has the route `/`, `https://localhost` shows a not-found error page. That's expected: sign in and build the site from the admin, starting with [Your First Layout](/guides/your-first-layout).
::

## 3. Open the site

There is no dev server to start. `docker compose up -d` already runs the Nuxt dev server inside the `app` container, and Caddy proxies it:

| URL | What's there |
|-----|-------------|
| `https://localhost` | Your Nuxt application |
| `https://localhost/_api` | API (JSON-LD) |
| `https://localhost/login` | Sign in |
| `https://localhost/_cwa` | CWA admin panel |

::callout{icon="i-heroicons-light-bulb"}
The stack uses self-signed certificates. Accept the browser warning, or trust Caddy's local CA: it lives in the `caddy_data` volume, so copy it out with `docker compose cp php:/data/caddy/pki/authorities/local/root.crt .` and add `root.crt` to your system trust store.
::

::callout{icon="i-heroicons-information-circle"}
The containerised dev server is also published directly on `http://localhost:3001` if you ever need to bypass the proxy. Don't run `pnpm dev` on your host at the same time — that starts a *second* Nuxt on port 3000 that `https://localhost` never reaches.
::

Sign in at `https://localhost/login` with `admin` / `admin` (or the account you created). Click **Edit** to enter edit mode and see the inline CMS.

## Where things live

The project root holds the two applications side by side. Every path in these docs starts at the project root.

::DiagramFileTree
---
files:
  - path: api/src/Entity/Title.php
    label: a component's PHP entity
  - path: api/src/DataFixtures/AppScaffold.php
    label: the fixtures entry point
  - path: api/src/DataFixtures/Parts/CoreScaffoldPart.php
    label: seeds the layout, home page and Title
  - path: app/nuxt.config.ts
    label: registers layouts, pages and components
  - path: app/app/cwa/layouts/primary.vue
  - path: app/app/cwa/pages/PrimaryPageTemplate.vue
  - path: app/app/cwa/components/Title/Title.vue
  - path: compose.yaml
---
::

::callout{icon="i-heroicons-folder"}
**The Nuxt app is `app/`, and its source directory is `app/` too**, so CWA's Vue files live in `app/app/cwa/`, not `app/cwa/`. Nuxt only looks in `app/app/cwa/`, so a file created at `app/cwa/` from the project root is never found.
::

Commands run from the project root unless a page says otherwise. PHP and Composer run only inside Docker, so PHP commands go through the `php` container: `docker compose exec php bin/console …`.

## What Docker handles automatically

When the `php` container starts, the entrypoint:

- Runs `composer install` if `vendor/` is empty
- Generates the JWT key pair for authentication with `lexik:jwt:generate-keypair --skip-if-exists`, outside production. The keys go in `api/config/jwt/` (gitignored), encrypted with the `JWT_PASSPHRASE` in `api/.env`. To deploy, see [Docker → JWT keys](/deployment/docker#jwt-keys)
- Waits for PostgreSQL to be ready
- Runs pending database migrations
- Runs `ANALYZE` to refresh PostgreSQL query statistics (keeps dev pages fast — see [the Docker gotchas](/deployment/docker#common-gotchas))

The `app` container runs `pnpm install` and then the Nuxt dev server each time it starts. You never need to run these manually. Fixtures are the exception: they're never loaded automatically.

## CI/CD

If you chose **GitHub Actions** during setup, three workflows are pre-wired in `.github/workflows/`:

| Workflow | Trigger | What it does |
|----------|---------|-------------|
| `ci.yml` | Every push | Build + test; deploy a review environment for every branch except `main` |
| `production.yml` | Manual | Deploy canary or production |
| `cleanup.yml` | PR closed | Tear down review environment |

Images push to GHCR. The workflows use the same `bin/devops/` shell scripts as the GitLab CI option. Required secrets and variables are documented inline in each workflow file — read those.

::callout{icon="i-heroicons-information-circle"}
The template repo also has a `publish-create-cwa.yml` workflow, which publishes the CLI. `create-cwa` leaves it out of new projects. A project created before 21 September 2026 may still have it. It only fires on `create-cwa/v*` tags, so it never runs for you, but you can delete it: `rm .github/workflows/publish-create-cwa.yml`.
::

## Manual setup (alternative)

If you prefer to create a GitHub repository first and clone from there:

**With the GitHub CLI:**

```bash
gh repo create my-website \
    --template="components-web-app/components-web-app" \
    --private --clone
```

**Or generate from GitHub:**

::callout
---
icon: i-simple-icons-github
target: _blank
to: https://github.com/new?template_name=components-web-app&template_owner=components-web-app
---
Generate a new repository from the template on GitHub
::

Then, from the cloned project's root, start the stack:

```bash
docker compose up -d
```

Installing the Nuxt dependencies on your machine (`pnpm install` in `app/`) is optional, as in step 1: the `app` container installs them. Then follow steps 2 and 3 above. A clone keeps every feature and all the fixtures, because nothing is stripped, so loading fixtures seeds the full demo site. Turning features off is up to you.

::callout{icon="i-heroicons-information-circle"}
The template repo includes a `packages/` directory used for the `create-cwa` CLI itself. Delete it from your project after cloning — it's not needed in your app.

```bash
rm -rf packages/
```
::
