Your `landing` layout is in place — but its `<slot />` is empty. A page template fills it. It's a Vue file that defines the regions for a page: where the main content goes, where the sidebar lives.

Each region is a `CwaComponentGroup`. You declare which regions exist and what they're called; editors fill them with components at runtime. The template's `PrimaryPageTemplate.vue` has a single region; this guide builds a two-column one beside it.

## The File

Create `app/app/cwa/pages/TwoColumnPageTemplate.vue`:

```vue
<template>
  <div class="mx-auto grid max-w-7xl gap-10 px-4 py-10 md:grid-cols-3">
    <div class="md:col-span-2">
      <CwaComponentGroup
        reference="main"
        :location="props.iri"
      />
    </div>
    <aside>
      <CwaComponentGroup
        reference="aside"
        :location="props.iri"
      />
    </aside>
  </div>
</template>

<script setup lang="ts">
import type { IriProp } from '#cwa/composables/cwa-resource'

const props = defineProps<IriProp>()
</script>
```

### Key points

**`defineProps<IriProp>()`** — every page template receives its page's IRI as a prop. The module passes this automatically when rendering the page.

**`CwaComponentGroup reference="main" :location="props.iri"`** — creates a content region called `main` owned by this page. Any components the editor adds here are stored against this specific page record. Each `CwaComponentGroup` with a unique `reference` is a separate, independently managed region, so `aside` is a second one.

::callout{icon="i-heroicons-information-circle"}
The `location` must be the IRI of a **layout, page, or component**. For page regions, always use `props.iri` — the IRI the module passes in automatically for the current page.
::

## Register in nuxt.config

Add an entry next to the template's `PrimaryPageTemplate`:

```ts
// app/nuxt.config.ts
cwa: {
  pages: {
    PrimaryPageTemplate: {
      // the template's existing entry
    },
    TwoColumnPageTemplate: { // [!code focus]
      name: 'Two Column Page', // [!code focus]
    }, // [!code focus]
  }
}
```

The key is the filename. Add `classes` as you did for the layout if this template needs style options; it works the same way.

## Create a Page Record

A page template Vue file defines the structure; a Page record in the database gives it a URL and assigns it to a layout.

**Naming convention:** the page template's global component name is the filename prefixed with `CwaPage` — `TwoColumnPageTemplate.vue` → `CwaPageTwoColumnPageTemplate`. Unlike layouts, the admin's dropdown stores the short, unprefixed form (`TwoColumnPageTemplate`), while the fixture builder writes the prefixed form. Both resolve to the same component: the module strips and re-applies the prefix when it resolves `uiComponent`, so don't be alarmed if a page you created in the admin and one you seeded from fixtures show different values.

### Via the admin

Go to `/_cwa/pages` → the **+** button → choose **Two Column Page** as the **Page UI** (stored as `uiComponent: TwoColumnPageTemplate`), choose the `landing` layout, and click **Add Now**. The page opens on its **Routes** tab: create a route with the path `/landing`.

### Via fixtures

Add the page to `build()` in `api/src/DataFixtures/Parts/LandingScaffoldPart.php`, after the layout:

```php
public function build(CwaFixtureBuilder $cwa, ScaffoldState $state): void
{
    $cwa->layout('landing', 'Landing');

    $cwa->page('landing-page', 'TwoColumnPageTemplate', layout: 'landing', route: '/landing') // [!code focus]
        ->title('Landing'); // [!code focus]
}
```

`layout: 'landing'` refers to the layout's reference from `$cwa->layout('landing', …)`, not its `uiComponent`. The route is `/landing`, because the template's own home page already has `/`. Load it again from the project root:

```bash
docker compose exec php bin/console doctrine:fixtures:load --append
```

The layout already exists, so it's kept; the page and its route are created. See [Data Fixtures](/api/data-fixtures) for the full API.

Visit `https://localhost/landing`: the landing layout's banner and footer wrap your empty two-column page. Sign in and click **Edit** to see a **+** in each region.

## Template Pages for Dynamic Content

Static pages (home, about, contact) map one-to-one: one URL, one page. But for repeating content — blog articles, events, products — you want the **same page structure** reused across many URLs. For this, you create a **template page**:

```php
$cwa->page('article-template', 'TwoColumnPageTemplate', layout: 'landing', isTemplate: true);
```

A template page has no URL. Instead, each article (or product, or event) is a **PageData** record that references this template and gets its own URL. All those records share the regions you've defined in `TwoColumnPageTemplate.vue`, but each has its own data. If you picked the blog feature, the template's `BlogScaffoldPart` seeds a working example.

::callout{icon="i-heroicons-information-circle"}
In the admin, **blue** records are static pages, **yellow** are template pages, and **green** are PageData records (individual articles, products, etc.) — shown **orange** until they have a route. This colour coding makes it easy to see what's a shared structure vs. an individual piece of content.
::

The full dynamic pages pattern — how PageData records work, how to bind component positions to data fields — is in [Dynamic Pages](/core-concepts/dynamic-pages).
