---
title: Upgrading the Template
description: The steps for bringing a project made from the components-web-app template up to each template release, newest first.
---

A project made with `create-cwa` is a copy of the [components-web-app](https://github.com/components-web-app/components-web-app) template at one release. The template doesn't update your project for you: you copy the changes you want. Each section below covers one template release, newest first, with what to copy, which CI variables to set or remove, which images to rebuild, and whether Cloudflare needs a **Purge Everything**. Work through every section between your project's release and the one you're moving to, oldest first. The other deployment pages describe the current template only.

The template's [`CHANGELOG.md`](https://github.com/components-web-app/components-web-app/blob/main/CHANGELOG.md) has the full list, with a link to each commit to copy from. A template release pins a bundle and a `@cwa/nuxt` release; their own steps are in [Upgrading the Bundle](/api/upgrading).

::callout{icon="i-heroicons-information-circle"}
**Rebuild the API image** whenever a step changes `api/Dockerfile`, `api/frankenphp/Caddyfile` or a Souin patch: `docker compose build php && docker compose up -d php` locally, or a normal pipeline run. A Caddyfile that uses a new Caddy module can't load on an old image.
::

## Unreleased on `main`

After `2.0.0-alpha.15` ([!12](https://gitlab.com/silverback-web-apps/cwa/components-web-app/-/merge_requests/12), [#123](https://github.com/components-web-app/components-web-app/issues/123), [`095c074`](https://github.com/components-web-app/components-web-app/commit/095c074eba4a660412fad08c74a6415c11591115), [#125](https://github.com/components-web-app/components-web-app/issues/125), [`e15f168`](https://github.com/components-web-app/components-web-app/commit/e15f16818a61f9a3f68697808bea5998bf34b0dc), [`13243ae`](https://github.com/components-web-app/components-web-app/commit/13243aea131252dd9be88174b9d57a5b35a44864)).

- [ ] **Copy `run_test_functional` from `bin/devops/k8s.sh` and add `MAILER_DSN=null://null` to `api/.env.test`.** Both are needed. The job unsets `MAILER_DSN` and `MAILER_EMAIL`, so a test that sends email can't deliver it through your live relay, and the null transport stops tests falling back to `api/.env`'s `smtp-relay`, which CI doesn't have. See [CI/CD → Test](/deployment/ci-cd#test).
- [ ] Optional: add a `GITHUB_TOKEN` CI variable, a fine-grained token with no permissions. Copy the composer `RUN` step from `api/Dockerfile`, `build_api` from `bin/devops/k8s.sh`, the `COMPOSER_AUTH` block at the end of `bin/devops/setup.sh`, and the build step's `GITHUB_TOKEN` line in `.github/workflows/ci.yml`. Never set the variable to an empty value. See [CI/CD → Composer](/deployment/ci-cd#composer).
- [ ] **Delete any `VARNISH_TOKEN` CI variable.** Copy the deploy values in `k8s.sh`, and `helm/cwa/values.yaml` without `apiSecretToken`, which nothing read.
- [ ] Optional: copy `create_docker_pull_secret` from `k8s.sh` (it now uses `kubectl apply`, so releases sharing a namespace don't race). The first deploy prints a one-off warning about a missing `last-applied-configuration` annotation. If you run `helm lint` or `helm template`, copy `jwt-passphrase | default ""` from `helm/cwa/templates/secrets.yaml`.
- [ ] **Canary's SSR minimum is now 1 pod.** To keep 2, set `PWA_AUTOSCALE_MIN` (it applies to every track) or copy the deploy track `case` from `k8s.sh`. See [CI/CD → Autoscaling](/deployment/ci-cd#autoscaling).
- [ ] **Delete any `NUXT_CWA_API_URL`, `NUXT_PUBLIC_CWA_API_URL`, `NUXT_PUBLIC_CWA_API_URL_BROWSER` or `NUXT_PUBLIC_CWA_ENVIRONMENT` CI variable** before your first deploy with the site settings change ([`497e8ac`](https://github.com/components-web-app/components-web-app/commit/497e8ac74cf3ba8b066982df0192bff238abd906)). Every `NUXT_*` CI variable now reaches the Nuxt pods, and the deploy fails on a name the chart sets itself. See [CI/CD → Site settings](/deployment/ci-cd#site-settings).
- [ ] **Copy the site settings passthrough.** From `bin/devops/k8s.sh`: `deploy`, `build_app`, and the `site_env_*` and `cwa_environment_name` functions with the `SITE_ENV_RESERVED_*` lists. From the chart: `templates/site-env.yaml`, the `cwa.siteEnvFrom` helper and `CWA_ENVIRONMENT` in `cwa.phpEnv` (`_helpers.tpl`), the `envFrom`, `NUXT_PUBLIC_CWA_ENVIRONMENT` and `checksum/site-env` entries in `deployment.yaml`, `pwa-deployment.yaml` and `orphan-scan-cronjob.yaml`, and `siteEnv`/`cwaEnvironment` in `values.yaml`.
- [ ] If your own chart sets extra `env:` entries, add their names to `SITE_ENV_RESERVED_API` or `SITE_ENV_RESERVED_PWA` in `k8s.sh`, so a CI variable of the same name fails the deploy instead of being ignored.
- [ ] **GitHub projects: copy `bin/devops/github-export-secrets.sh` and its step** (*Expose NUXT_\* and CWA_API_\* secrets to the deploy*) into each deploy job in `ci.yml` and `production.yml`, after the kubectl and Helm setup actions and before the deploy ([`75a416b`](https://github.com/components-web-app/components-web-app/commit/75a416bc14edcdd601918bf44fa291f391abcbcf)). Never add it to a build job. See [CI/CD → On GitHub](/deployment/ci-cd#on-github).
- [ ] Move any site setting passed as a Docker build arg or build secret to a runtime variable: `runtimeConfig` in Nuxt, `%env()%` in Symfony.
- [ ] **Rename any `POSTGRES_USERNAME` CI variable to `POSTGRES_USER`**, and copy `yaml_squote`, `postgres_auth_yaml` and the `postgresql:` block of `deploy` from `k8s.sh`, and `database-url` from `helm/cwa/templates/secrets.yaml` ([`e15f168`](https://github.com/components-web-app/components-web-app/commit/e15f16818a61f9a3f68697808bea5998bf34b0dc)). With the in-cluster PostgreSQL, `POSTGRES_USER`, `POSTGRES_PASSWORD` and `POSTGRES_DB` never took effect before this: every in-cluster database ran as `example` / `!ChangeMe!` / `api`. See [CI/CD → Database](/deployment/ci-cd#database).
- [ ] On GitLab, a `POSTGRES_*` variable with the **All** environment scope now also reaches the `functional tests` job, for both its database and its URL. Scope these variables to your deploy environments.
- [ ] Optional: copy the `KUBERNETES_VERSION` and `HELM_VERSION` lines from `bin/devops/setup.sh`, so a GitLab CI variable can choose the versions, as it already could on GitHub ([`13243ae`](https://github.com/components-web-app/components-web-app/commit/13243aea131252dd9be88174b9d57a5b35a44864)). The defaults stay `1.31.0` and `3.19.0`.

::callout{icon="i-heroicons-exclamation-triangle" color="warning"}
**If you already set `POSTGRES_USER` (or `POSTGRES_USERNAME`), `POSTGRES_PASSWORD` or `POSTGRES_DB`, the next deploy changes the in-cluster database.** A new user or database name restarts the PostgreSQL pod empty, so load fixtures again. A new password alone doesn't restart it, and the API can't connect until you run `kubectl delete pod <release>-postgresql-0` after the deploy, which also starts it empty, because the chart runs PostgreSQL without persistence. To keep today's database, delete the variables instead.
::

Images: rebuild the API image if you copied the composer step. Cloudflare: no purge needed.

## 2.0.0-alpha.14

Released 2026-10-08.

- [ ] **Keep `CLUSTER_ISSUER=letsencrypt-prod` on every production site**, and check it exists **before** you copy `bin/devops/setup.sh`. An unset `CLUSTER_ISSUER` gives `letsencrypt-staging` again, whose certificates browsers don't trust. alpha.12's advice that it could be deleted is withdrawn. An empty value still turns cert-manager off. See [CI/CD → Kubernetes](/deployment/ci-cd#kubernetes).
- [ ] **Serve the service worker through `@vite-pwa/nuxt`.** Replace alpha.13's `routeRules` `/sw.js` block in `app/nuxt.config.ts` with `registerWebManifestInRouteRules: true` in the `pwa` block. It sends `/sw.js` and the manifest with `public, max-age=0, must-revalidate`. Without that header on `/sw.js`, add a Cloudflare Cache Rule that bypasses the cache for `/sw.js` only, or visitors get updates up to two hours late. See [PWA → Serving the service worker](/nuxt-module/pwa#serving-the-service-worker).
- [ ] **Cloudflare:** set Browser Cache TTL to **Respect existing headers** (Caching → Configuration). A 4-hour default turned `/sw.js`'s `max-age=0` into `max-age=14400` for browsers ([#120](https://github.com/components-web-app/components-web-app/issues/120)). See [Cloudflare → Leave Cloudflare's cache alone](/deployment/cloudflare#leave-cloudflares-cache-alone).

Images: rebuild the app image. Cloudflare: no purge needed.

## 2.0.0-alpha.11

Released 2026-10-08.

## 2.0.0-alpha.4

Released 2026-10-05. A large release: Mercure 1.0, origin protection, working Cloudflare purges and PHPUnit in place of Behat. Pins bundle `2.0.0-alpha.8` and `@cwa/nuxt` `2.0.0-alpha.5`; see [Upgrading the Bundle → 2.0.0-alpha.8](/api/upgrading#_200-alpha8).

**API image and Caddyfile:**

- [ ] **Rebuild the API image before you deploy this Caddyfile.** It uses two new Caddy modules (`query_allowlist`, `rate_limit`), and an old image refuses it ([`4cbe05a`](https://github.com/components-web-app/components-web-app/commit/4cbe05a949518be7da67995f6d247807e7a39b7f), [#106](https://github.com/components-web-app/components-web-app/issues/106)). If your pages read a query parameter other than `page`, `search` or `order[...]`, add it to `CACHE_QUERY_ALLOWLIST`, or server-side rendering stops seeing it. Never add `cwa_force` back: an anonymous `?cwa_force=<anything but true>` sent the server render into a redirect loop ([`3f7130f`](https://github.com/components-web-app/components-web-app/commit/3f7130f73ee2cdfab4579a26aefe2e4fd9dc0465)). Behind a proxy with public addresses other than Cloudflare's, add its ranges to `CADDY_TRUSTED_PROXIES`. See [CI/CD → Origin Protection](/deployment/ci-cd#origin-protection). Load-test cold runs now get cache hits unless `k6cb` is allowlisted; see [Load Testing](/deployment/load-testing).
- [ ] **Mercure 1.0, in the same deploy as the bundle and module updates** ([`28fa2bb`](https://github.com/components-web-app/components-web-app/commit/28fa2bb2b989fcdff007d84676931ed68e3a922e), [`1a9f7a5`](https://github.com/components-web-app/components-web-app/commit/1a9f7a5ea2a43f6d314f9c00f18137a241be3567), [#67](https://github.com/components-web-app/components-web-app/issues/67)). Copy `api/config/packages/mercure.yaml` and the Caddyfile's `mercure` block. If `MERCURE_EXTRA_DIRECTIVES` sets `demo` or `ui`, use `debugger` (dev only). See [Bundle Setup → Mercure Hub](/api/bundle-setup#mercure-hub).
- [ ] **The chart requires `mercure.publicUrl`** ([`b3b8622`](https://github.com/components-web-app/components-web-app/commit/b3b8622d3fc1375da564668aab3dea9053e1807f)). Copy `api/frankenphp/souin/v1.7.9-singleflight-fix.patch` with its `api/Dockerfile` lines, the `kube-probe/` exclusion in the Caddyfile's `@use_cache`, and the probes in `helm/cwa`, then recreate the API pod. - [ ] Remove `use_symfony_listeners: true` from `api_platform.yaml`, unless your own code hooks API resources through `EventPriorities` or `kernel.view`/`kernel.request` ([`fc0afb7`](https://github.com/components-web-app/components-web-app/commit/fc0afb71bc7274db9cc6e3dd4ff51dbb64874650)).

**CI:**

- [ ] **Behat is gone** ([`8885b3c`](https://github.com/components-web-app/components-web-app/commit/8885b3c01adafbe6e37263553d84ae9cd572b714)). `behatch/contexts` was archived, and API Platform itself tests with PHPUnit. API tests are PHPUnit functional tests on API Platform's `ApiTestCase` (`api/tests/Functional`, base class `FunctionalTestCase`). The `behat tests` job is now `functional tests` (`run_test_functional`; GitHub: `functional-tests`), and production and canary need it instead. The template dropped `behat.yml`, `features/`, `scripts/patch-behat.php`, the Behat, Mink, behatch and FriendsOfBehat packages, and `run_test_behat`. A project with its own Behat features ports them to `tests/Functional`, or keeps those files, the function and its CI job.
- [ ] **GitHub projects: copy `bin/devops/github-export-vars.sh` and the step that runs it** from the template's workflows ([`8f290d8`](https://github.com/components-web-app/components-web-app/commit/8f290d85d234a60da74b0eec6be8294764b7e842), [#91](https://github.com/components-web-app/components-web-app/issues/91)). Without it, GitHub jobs only see the variables a workflow names, so anything else `k8s.sh` reads silently uses its default: `INGRESS_ENABLED` (so a GitHub deploy gets no ingress), and the TLS, sizing and `PHP_MEMORY_LIMIT` variables. Variables you had added to a workflow's `env:` can stay. Check none holds a stale value you were relying on GitHub to ignore.
- [ ] pnpm 12: remove `confirmModulesPurge` from `pnpm-workspace.yaml`, or pnpm refuses to run ([`e919d06`](https://github.com/components-web-app/components-web-app/commit/e919d069d24b7e74f59395d49772b394a70b036d)).

**Cloudflare:**

- [ ] **Take the patched Souin and the `Cache-Tag` rule** ([`cd99b55`](https://github.com/components-web-app/components-web-app/commit/cd99b5541becc7e9b5539c29e2bb929769e97842), [#108](https://github.com/components-web-app/components-web-app/issues/108)). Unpatched Souin v1.7.9 posts to `/zones/<id>/purge` instead of `/purge_cache`, so no purge reached Cloudflare and the failure was silent. The patch fixes the endpoint, accepts a scoped token and logs failures. Earlier projects also sent no `Cache-Tag`.
- [ ] **Take the regenerated `v1.7.9-cloudflare-purge.patch` and the `purge_rendered_html` change in `bin/devops/k8s.sh`** ([`6a8c898`](https://github.com/components-web-app/components-web-app/commit/6a8c8984b1408d48fced26655ad32b83afcbaeac)). A full flush then purges everything at Cloudflare, and with `provider cloudflare` the deploy runs `purge-http-cache` instead of `purge-rendered-html`. Before, a full flush cleared only Souin's own store and the deploy purged only the `cwa-html` tag, so you had to **Purge Everything** in Cloudflare after each full flush, and after any release that changed API output if you use the API rule.
- [ ] **If you added the optional API rule**, add `and not starts_with(http.request.uri.path, "/_api/_/component_positions/")` to it, then do one Purge Everything ([`39c5f4a`](https://github.com/components-web-app/components-web-app/commit/39c5f4a97d71e2e1edbdb7b5cb38440a4b247ddc), [docs#134](https://github.com/components-web-app/docs/issues/134)). Page-data positions vary by the `path` request header, which Cloudflare ignores, so page-data pages showed one page's content after client-side navigation. See [Cloudflare → API responses](/deployment/cloudflare#api-responses-optional).
- [ ] **If the pages Cache Rule went in before this deploy, do one Purge Everything after it.** Until a deploy sends `Cache-Tag`, Cloudflare stores untagged pages, which can't be purged by tag, and after the next front-end deploy they point at `/_nuxt/*` files that no longer exist. A Purge Everything before that deploy doesn't help: the old image refills the edge with untagged pages straight away. From this release on, a deploy purges everything itself.

Images: rebuild both. Cloudflare: Purge Everything once, after this deploy, if Option B or the API rule was already on.

## Before 2.0.0-alpha.1

`2.0.0-alpha.1` (2026-09-24) is the template's first tagged release. A project generated before it may also need these:

- [ ] **GitLab merge request pipelines** ([`cf9c665`](https://github.com/components-web-app/components-web-app/commit/cf9c665e4d3c319e35e50c090887981738a840aa)). Earlier projects also create a merge request pipeline that holds only the unit tests. It fails, because no image has been built for it, and **Pipelines must succeed** then blocks the merge request. Add a `workflow:` rule with `if: $CI_PIPELINE_SOURCE == "merge_request_event"` and `when: never`, and limit the `unit tests` job to `branches`.
- [ ] **Production waits for builds and tests** ([`1280520`](https://github.com/components-web-app/components-web-app/commit/12805209f2e63ab7d029133e675837617d9a0a1d)). Earlier, production and canary needed only `staging`, so with `STAGING_ENABLED=false` the manual deploy could start before the images were built, deploy the previous `main` image and ignore failing tests. Add `build api`, `build app`, `unit tests` and the test job to the `needs` of both jobs in `.gitlab-ci.yml`, each with `optional: true`.
- [ ] **Cache warm exit code `141`** ([`6123387`](https://github.com/components-web-app/components-web-app/commit/612338799a4f642d1fd687537f834b39bd4c85d2)). A GitLab warm job could fail with `141` after every page returned `200`: `warm_cache` ended with `sort | head -3`, and under `pipefail` the `SIGPIPE` failed the job. In `bin/devops/k8s.sh`, replace `head -3` with `sed -n '1,3s#^#  #p'` (and drop the `sed` after it), and use `sed -n 1p` instead of `head -1` in other pipes.
- [ ] Delete `.github/workflows/publish-create-cwa.yml` if your project has it. It publishes the template's scaffolding CLI.
