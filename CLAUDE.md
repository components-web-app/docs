# CWA Docs - Claude Context

## Docs writing principles

- **Getting started guides = simple introductions.** One concept per guide, minimum viable code, link out to the detailed reference for everything else. Readers should feel like they're learning and building, not reading a reference manual.
- **Don't repeat the intro.** Each guide should build on what the previous page established — not re-explain the same concept.
- **Callouts for key constraints.** Constraints like "location must be a layout, page, or component IRI" belong in a callout, not buried in prose.
- **Image/video placeholders as you go.** Add `::callout{icon="i-heroicons-photo"}` placeholders describing what each image/video should show. This makes visual gaps explicit.
- **Consistent structure per guide.** Each guide: brief framing → the file → register in config → create in API (admin + fixtures) → next step.
- **Code focus.** Use `// [!code focus]` on key lines when showing context-heavy blocks.

### 2026-08-12 — docs #1 (AI chat assistant): provider decided, not yet built
Researched and recorded on the issue (body + [findings comment](https://github.com/components-web-app/docs/issues/1#issuecomment-5268193154)). **NotebookLM — the original inspiration — cannot be the backend:** no consumer API, and the Gemini Notebook Enterprise API (`v1alpha` preview) is notebook/source **management only** (`notebooks.create/get/listRecentlyViewed/batchDelete/share` + podcasts) with **no query or chat endpoint**. Only free NotebookLM path is a public shared notebook linked out to. **Decision: lexical retrieval + Claude Haiku 4.5 (paid) behind an `/api/chat` edge function** (~$0.012/turn, ~$6/mo at 500 turns; Groq free tier was the earlier pick and is superseded). Key reasoning worth keeping: (1) **`llms-full.txt` is ~165–190k tokens** — full-context stuffing costs ~$0.45 per *cold* prompt-cache write and the 5-min TTL means low traffic goes cold nearly every time, so **low traffic makes full-context worse, not cheaper**; retrieval (~8k tokens/turn) sidesteps it and BM25 over our own docs needs no embeddings service. (2) **The Gemini free tier trains on submitted content and human reviewers may read inputs/outputs** ([official terms](https://ai.google.dev/gemini-api/terms)) — the exposure is *visitor* questions, not our public docs, so it needs a privacy notice; Groq retains nothing by default with ZDR on all tiers. Being FOSS doesn't disqualify us from any free tier — Google's "professional or business purposes" wording is about who uses it, not commerciality. (3) **Self-hosting costs more, not less** (~$100–300/mo GPU VPS vs ~$24/mo hosted Haiku 4.5 at ~$0.012/turn); the docs site is prerendered to Vercel with nowhere to run inference. (4) **Pricing shape worth remembering: Haiku 4.5 sits *between* Gemini Flash-Lite and Flash** — Gemini 3.1 Flash-Lite $0.25/$1.50, Haiku $1/$5, Gemini 3.5/3.6 Flash $1.50/$7.50–9.00 — so "Gemini is cheaper" only holds at the Flash-**Lite** tier. Chose Haiku over Flash-Lite because the gap is ~$4.50/mo at our traffic while Google's model churn is much faster (2.5 Flash-Lite retires Oct 2026; 3.1/3.5/3.6 already out) for a widget nobody maintains. (5) **Gemini context caching bills ~$1.00/hour storage** (~$720/mo held continuously) on top of token cost — kills any "cache `llms-full.txt`" idea there outright; Anthropic caching has no storage fee. (6) **Persona design:** the RAG grounding rule and the "use metaphors" instruction actively conflict — must split the permission explicitly (*metaphors are the model's to invent, facts are not*) or it improvises product behaviour from WordPress/Strapi. Starter system prompt + seed metaphors (picture frame with labelled slots, one blueprint many houses, shop window vs stockroom, kitchen vs dining room) are in the issue comment; explicitly forbid "it's like WordPress". Note **prompt caching won't fire on Haiku 4.5** for a persona prompt — 4096-token minimum prefix. *Docs impact: none yet — this is a site feature, not documentation. ### 2026-08-12 — cwa-nuxt-module: a resource IRI is a route *param*, never a path (bare-IRI navigation always 404s)
Admin bug fix. Viewing a resource with no public route works **only** via `getInternalResourceLink(iri)` → `{ name: '_cwa-resource-page', params: { cwaPage0: iri } }`; `cwaPage0` exists solely on the `/_cwa/:cwaPage0` route, while the module's own catch-alls are `/`, `/:cwaPage1`, `/:cwaPage1/:cwaPage2`… So `navigateTo(pageIri)` with a bare IRI string matches a catch-all with no `cwaPage0`, and the fetcher requests `/_/routes/` + the **whole IRI** — a primary fetch that can only 404, taking over the screen while the URL stays put. Fixed where the admin deliberately falls back to the IRI view after you delete the route you are viewing (`RoutesTab`, `RouteRedirectsTree`). *Docs impact: low but real — if any page shows navigating to a CWA resource programmatically, it must use `getInternalResourceLink()` (or `getResourceRoute()`), never the IRI as a path.*

### 2026-08-12 — cwa-nuxt-module: deleting the page you are on now redirects to the admin listing
Admin UX fix, no API surface. Deleting a page from the **header page-settings modal** used to leave the admin on a 404 — the redirect ran from `saveCompleteFn`, i.e. *after* the resource (and its cascade) had already been removed from the store. `PageResourceAdminModal` now navigates from `requestCompleteFn` (before the removal) and awaits it: a **Page → `/_cwa/pages`**, a **PageData → its data-type listing `/_cwa/data/{type}`** (falling back to `/_cwa/data`). ### 2026-08-12 — api-components-bundle #205/#206/#207/#208 (PR #209): uploaded files disappearing on publish
Four bug fixes around `#[Uploadable]` + `#[Publishable]`. Cause (**#205**): the "file was explicitly cleared" marker (`PATCH {"file": null}`) was recorded on the shared `UploadableFileManager` as a bare storage-property name — `filename`, the default for *every* `UploadableField` — and never cleared, so it applied to whatever was written next; under **FrankenPHP worker mode** it also outlived the request, so one admin file deletion deleted the file of every later publish served by that worker. ## Key Technical Notes

### app.config.ts UI overrides format
Use the `slots` wrapper — direct slot keys at top level cause TS errors:
```ts
ui: {
  pageHero: {
    slots: { container: '...', title: '...' }
  }
}
```

### Comark (replaces @nuxtjs/mdc)
- Module: `@comark/nuxt` (installed, added to nuxt.config.ts modules)
- Component: `<Comark>{{ content }}</Comark>` — content goes in the DEFAULT SLOT not a prop
- HTML content (with `<br>`, `<span>` etc.): use `v-html` instead of Comark
- Syntax highlighting: import `highlight` from `@comark/nuxt/plugins/highlight`, pass via `:plugins="[highlightPlugin]"`
- Theme config: `highlight({ themes: { light: 'github-light', dark: 'github-dark' }, languages: [...] })`
- Docs: https://comark.dev/

### @nuxt/content v3 content refresh
If you see "no such table: _content_docs": `rm -rf .nuxt && pnpm run dev`

### Badge frontmatter in docs pages
- Must be declared in `content.config.ts` schema or Nuxt Content v3 strips it at query time
- `UPageHeader` in v4 has no `badge` prop — render via `#headline` slot with `<UBadge>`
- Valid color tokens: `primary`, `secondary`, `success`, `info`, `warning`, `error`, `neutral` (not `amber`)

### `npx cwa make:component` — what it does and doesn't do
Source: `bin/cwa.mjs` in `cwa-nuxt-3-module`. It **only creates the Vue file** and **prints** the matching `php bin/console make:api-component` command — it does NOT run it. The PHP command must be run manually in the API project. Guide order: npx first (scaffolds Vue + outputs the PHP command to copy), then run that printed command in the API project.
